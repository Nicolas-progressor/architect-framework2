# Описание системы Architect RED 2

## Общая информация

**Architect RED 2** — это PHP-фреймворк, построенный на основе statement-based MVC архитектуры. Фреймворк использует строгую типизацию (PHP 8.1+), PSR-4 автозагрузку и контейнер зависимостей (DIC). Предназначен для создания модульных веб-приложений с поддержкой нескольких приложений в рамках одного экземпляра.

**Ключевые особенности:**
- **Statement-based MVC** — жизненный цикл приложения управляется через statement-ы (этапы выполнения).
- **Контейнер зависимостей** — Singleton-контейнер для управления сервисами.
- **Модульная система** — общие модули и шаблоны для всех приложений.
- **Environment Manager** — гибкая система определения окружения (development, testing, staging, production).
- **Unit-ы** — вспомогательные классы через Composer.
- **Поддержка нескольких приложений** — возможность разделения функционала на отдельные приложения (home, admin и др.).
- **Расширяемость** — архитектурные расширения (Blueprint, Axiom ORM, Auth System) подключаются как Composer-пакеты.

## Основные компоненты

### 1. Ядро фреймворка

- **Container** (`architect/Core/Container.php`) — контейнер зависимостей (синглтон), управляет сервисами.
- **Statement** (`architect/Core/Statement.php`) — система statement-ов, управляет жизненным циклом приложения.
- **Framework** (`architect/Core/Framework.php`) — основной класс приложения, запускает statement-ы.
- **EnvironmentManager** (`architect/Core/EnvironmentManager.php`) — управление окружением, загрузка конфигурации.

### 2. Сервисы

Сервисы регистрируются через `ServiceProvider` и доступны через контейнер:

| Сервис | Назначение |
|--------|------------|
| `environment` | Управление окружением и конфигурацией |
| `config` | Конфигурация приложений |
| `logger` | Логирование (PSR-3) |
| `router` | Маршрутизация URL |
| `apps` | Управление приложениями |
| `template` | Шаблонизатор |
| `view` | Представление |
| `model` | Модель |
| `language` | Язык и переводы |
| `pattern` | Обработчик MVC |
| `errors` | Обработка ошибок (PSR-3, DI) |
| `debug` | Отладочная панель с интерактивным UI |
| `form` | Управление формами, валидация, CSRF |

### 3. Конфигурация

Конфигурация хранится в JSON-файлах в папке `app/config/`:

- **config.json** — общие настройки приложения.
- **apps.json** — конфигурация приложений.
- **router.json** — настройки роутера.
- **debug.json** — конфигурация отладочной панели.
- **blueprint.json** — настройки шаблонизатора Blueprint.
- **auth.json** — настройки системы аутентификации.
- **database.json** — настройки базы данных для ORM Axiom.
- **environment/{env}.json** — настройки окружения (development, testing, staging, production).

Окружение определяется через переменную `APP_ENV` (из .env файла, переменной окружения или константы). Настройки окружения переопределяют общие настройки.

### 4. Модули и приложения

**Приложения** — отдельные функциональные блоки (например, home, admin). Каждое приложение имеет свою структуру модулей, шаблонов, маршрутов и конфигурации.

**Модули** — MVC-компоненты, содержащие контроллеры, модели, представления, виджеты и языковые файлы. Модули могут быть:
- **Прикладные** — расположены в `app/apps/{app}/modules/`, доступны только для данного приложения.
- **Общие** — расположены в `app/modules/`, доступны всем приложениям.

**Приоритет поиска модулей:**
1. Модули приложения
2. Общие модули

### 5. Маршрутизация

Маршруты определяются в JSON-файлах в папках `app/routes/` (общие) и `app/apps/{app}/routes/` (прикладные). Роутер сопоставляет URL с модулем, контроллером и действием.

### 6. Шаблонизатор Blueprint

Blueprint — мощный шаблонизатор с синтаксисом, похожим на Blade/Twig. Особенности:
- Компиляция в PHP для высокой производительности.
- Наследование шаблонов (extends, block).
- Система layout (layout, section, yield).
- Более 40 встроенных фильтров и функций.
- Поддержка MVC Elements и Widgets.
- Автоматическое экранирование HTML.
- Интеграция с отладочной панелью.

Шаблоны ищутся в порядке приоритета: приложение → общие шаблоны.

### 7. ORM Axiom

Axiom — ORM-конструктор запросов для реляционных БД. Особенности:
- Поддержка MySQL, PostgreSQL, SQLite.
- ООП-интерфейс построения запросов (SELECT, INSERT, UPDATE, DELETE).
- Подготовленные выражения для защиты от SQL-инъекций.
- Транзакции, ленивая загрузка, агрегатные функции.
- Поддержка Entity-файлов (PHP-классы с аннотациями) и JSON ORM-файлов.
- Модули Many-to-Many, Cache, Migration.

### 8. Система аутентификации (Auth System)

Модульная система управления авторизацией (RBAC). Особенности:
- Роли и разрешения.
- Middleware для защиты маршрутов.
- Поддержка сессий и JWT-токенов.
- Конфигурация через JSON.
- Интеграция с фреймворком через Composer-пакет.

### 9. Отладочная панель (Debug)

Интерактивная панель в нижней части экрана с вкладками:
- ⏱️ Time — время выполнения по этапам.
- 💾 Memory — использование памяти.
- 🗄️ Database — SQL-запросы с подсветкой медленных.
- ⚠️ Logs — ошибки и предупреждения.
- 🔁 Cache — статистика кэширования.
- 🖐️ Session — данные сессии.
- ⚙️ Environment — конфигурация окружения.
- 🛠️ Debug — пользовательские данные.

Панель автоматически собирает данные через `DebugDataCollector`.

### 10. Формы (Form Service)

Полноценная система управления формами с валидацией, CSRF-защитой и генерацией HTML. Построена на принципах SOLID с поддержкой Dependency Injection.

## Жизненный цикл приложения

1. **Точка входа** — `htdocs/index.php` загружает `architect/bootstrap.php`.
2. **Инициализация окружения** — `EnvironmentManager` определяет окружение, загружает конфигурацию.
3. **Создание контейнера** — `Container` регистрирует сервисы через `ServiceProvider`.
4. **Запуск фреймворка** — `Framework::run()` выполняет statement-ы.
5. **Statement-ы**:
   - `core_preinit` — предварительная инициализация.
   - `core_init` — инициализация ядра, регистрация сервисов.
   - `core_load` — загрузка приложения, роутинг.
   - `core_post_load` — после загрузки.
   - `app_load` — загрузка данных модуля.
   - `app_data` — обработка данных (модель).
   - `app_output` — вывод (контроллер).
   - `render` — рендеринг представления.
6. **Обработка запроса** — роутер определяет маршрут, запускается соответствующий контроллер.
7. **Рендеринг** — шаблонизатор (Blueprint) генерирует HTML, который отправляется клиенту.

## Расширения и интеграции

- **Blueprint** — интегрирован как сервис `blueprint`, предоставляет функции `element`, `layout`, фильтры и т.д.
- **Axiom ORM** — интегрирован через `OrmServiceProvider`, предоставляет `QueryBuilder` и `EntityManager`.
- **Auth System** — предоставляет `AuthManager`, middleware, модели пользователей, ролей и разрешений.
- **Statics** — вспомогательные классы (хелперы) для работы с HTML, хлебными крошками, заголовками, запросами.

## Требования

- PHP 8.1+
- Composer
- Bootstrap 5.3.2 (опционально, для стандартных шаблонов)
- Поддерживаемые БД: MySQL ≥ 5.7, PostgreSQL ≥ 10, SQLite ≥ 3.8

## Быстрый старт

1. Клонировать репозиторий.
2. Установить зависимости: `composer install`.
3. Создать `.env` файл: `cp .env.example .env`.
4. Настроить веб-сервер на директорию `htdocs/`.
5. Запустить приложение через браузер.

## Заключение

Architect RED 2 — это современный, модульный и расширяемый PHP-фреймворк, предназначенный для разработки сложных веб-приложений. Благодаря statement-based архитектуре, контейнеру зависимостей и поддержке нескольких приложений он обеспечивает гибкость и удобство разработки. Интеграция с мощными компонентами (Blueprint, Axiom, Auth System) позволяет быстро строить безопасные и производительные решения.

Документация находится в папке `docs/` и включает руководства по установке, конфигурации, использованию сервисов, шаблонизатору, ORM и системе аутентификации.
