# Подход к интеграции новых компонентов

## Обзор
Этот документ описывает подход к интеграции новых компонентов (валидатор, менеджер сессий, пагинация, файловое хранилище, почта) с существующей архитектурой Architect Framework 2.

## Архитектурные принципы

### Совместимость с существующей системой
- Все новые компоненты должны интегрироваться с существующим контейнером зависимостей
- Новые компоненты должны использовать существующие интерфейсы и паттерны
- Обратная совместимость должна сохраняться на всех уровнях

### Сервис-провайдеры
- Каждый компонент должен предоставлять свой сервис-провайдер
- Сервис-провайдеры должны регистрироваться через механизм автоматического обнаружения
- Сервис-провайдеры должны поддерживать конфигурацию через JSON-файлы

### Конфигурация
- Все компоненты должны использовать существующую систему конфигурации
- Конфигурационные файлы должны следовать установленному формату
- Конфигурация должна поддерживать окружения (development, production, etc.)

## Интеграция с контейнером зависимостей

### Регистрация сервисов
```php
// В сервис-провайдере компонента
public function register(ContainerInterface $container): void
{
    $container->singleton('validator', function ($container) {
        return new \Architect\Validation\Validator($container);
    });
}
```
