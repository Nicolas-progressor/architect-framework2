# Архитектура Architect RED 2

## Обзор

Architect RED 2 — это PHP-фреймворк, построенный на основе **statement-based MVC** архитектуры. Фреймворк использует строгую типизацию (PHP 8.1+), PSR-4 автозагрузку и контейнер зависимостей (DIC). Основная цель — предоставить модульную, расширяемую и высокопроизводительную платформу для веб-приложений.

## Ключевые принципы

1. **Statement-based жизненный цикл** — приложение выполняется через последовательность statement-ов (этапов), что позволяет гибко встраивать логику на разных стадиях.
2. **Контейнер зависимостей** — все сервисы управляются через DI-контейнер, обеспечивая слабую связанность и тестируемость.
3. **Модульность** — система поддерживает несколько приложений и общие модули, что позволяет создавать сложные проекты с переиспользуемыми компонентами.
4. **Конфигурация через JSON** — настройки хранятся в JSON-файлах, поддерживаются окружения (development, testing, staging, production).
5. **Расширяемость** — фреймворк можно расширять через Composer-пакеты (Statics), подключаемые сервисы и middleware.

## Компоненты архитектуры

### 1. Ядро (Core)

Ядро фреймворка расположено в директории `architect/Core/` и включает:

- **Container** — контейнер зависимостей, реализующий паттерн Singleton. Управляет регистрацией, созданием и жизненным циклом сервисов.
- **Statement** — менеджер statement-ов, управляет жизненным циклом приложения через предопределённые этапы (core_preinit, core_init, core_load, app_data, app_output, render и др.).
- **Framework** — основной класс приложения, координирует работу контейнера и statement-ов, запускает приложение.
- **EnvironmentManager** — определяет текущее окружение, загружает конфигурацию, предоставляет доступ к настройкам.

### 2. Сервисы (Services)

Сервисы — это основные функциональные компоненты, регистрируемые в контейнере. Каждый сервис реализует определённую задачу:

- **Config** — управление конфигурацией приложений.
- **Logger** — логирование с поддержкой PSR-3.
- **Router** — маршрутизация URL.
- **Apps** — управление приложениями (home, admin и др.).
- **Template** — шаблонизатор (интеграция с Blueprint).
- **View** — рендеринг представлений.
- **Model** — создание экземпляров моделей.
- **Language** — интернационализация и переводы.
- **Pattern** — обработчик MVC-паттерна.
- **Errors** — обработка ошибок и исключений (PSR-3, DI).
- **Debug** — отладочная панель с интерактивным UI.
- **Form** — управление формами, валидация, CSRF-защита.

Сервисы регистрируются в `ServiceProvider` и доступны через контейнер по идентификатору (например, `$container->get('router')`).

### 3. Модули и приложения (Modules & Apps)

Фреймворк поддерживает несколько приложений в рамках одного экземпляра. Каждое приложение имеет свою структуру:

```
app/apps/{app}/
├── modules/          # Модули приложения
├── template/         # Шаблоны приложения
├── routes/           # Маршруты приложения
└── config/           # Конфигурация приложения
```

**Модуль** — это MVC-компонент, содержащий контроллеры, модели, представления, виджеты и языковые файлы. Модули могут быть:
- **Прикладные** — находятся в `app/apps/{app}/modules/` и доступны только для данного приложения.
- **Общие** — находятся в `app/modules/` и доступны всем приложениям.

Приоритет поиска модулей: сначала прикладные, затем общие.

### 4. Маршрутизация (Routing)

Маршруты определяются в JSON-файлах в папках `app/routes/` (общие) и `app/apps/{app}/routes/` (прикладные). Роутер сопоставляет URL с модулем, контроллером и действием. Поддерживаются параметры, условия и middleware.

### 5. Шаблонизатор Blueprint

Blueprint — это мощный шаблонизатор с синтаксисом, похожим на Blade/Twig. Он компилирует шаблоны в PHP для максимальной производительности и предоставляет:
- Наследование шаблонов (extends, block).
- Систему layout (layout, section, yield).
- Более 40 встроенных фильтров и функций.
- Поддержку MVC Elements и Widgets.
- Автоматическое экранирование HTML.
- Интеграцию с отладочной панелью.

Blueprint интегрирован как сервис `blueprint` и может использоваться как в контроллерах, так и в представлениях.

### 6. ORM Axiom

Axiom — это ORM-конструктор запросов для реляционных БД (MySQL, PostgreSQL, SQLite). Особенности:
- ООП-интерфейс построения запросов (SELECT, INSERT, UPDATE, DELETE).
- Подготовленные выражения для защиты от SQL-инъекций.
- Транзакции, ленивая загрузка, агрегатные функции.
- Поддержка Entity-файлов (PHP-классы с аннотациями) и JSON ORM-файлов.
- Модули Many-to-Many, Cache, Migration.

Axiom интегрирован через `OrmServiceProvider` и доступен через контейнер как `axiom`.

### 7. HTTP-клиент

Официальный пакет `architect/http-client` предоставляет полнофункциональный PSR-18 совместимый HTTP-клиент с поддержкой синхронных и асинхронных запросов, цепочками middleware, конфигурируемыми драйверами (cURL, stream, curl_multi) и интеграцией с DI-контейнером фреймворка.

Ключевые возможности:
- Мультидрайверная архитектура (cURL, stream, curl_multi для параллельных запросов).
- Цепочки middleware для логирования, кэширования, аутентификации и т.д.
- Автоматическая регистрация в DI через `HttpClientServiceProvider` (сервис `http_client`).
- Конфигурация через PHP-файл (`app/config/http-client.php`).
- Полная совместимость с PSR-7 и PSR-18.

HTTP-клиент предназначен для взаимодействия с внешними API, веб-сервисами и микросервисами. Подробная документация доступна в отдельном файле: [HTTP-клиент](../docs2/http-client.md).
### 8. Система аутентификации (Auth System)

Модульная система управления авторизацией (RBAC). Предоставляет:
- Роли и разрешения.
- Middleware для защиты маршрутов.
- Поддержку сессий и JWT-токенов.
- Конфигурацию через JSON.
- Интеграцию с фреймворком через Composer-пакет.

### 9. Отладка и логирование (Debug & Logging)

- **Debug панель** — интерактивная панель в нижней части экрана, отображающая информацию о времени выполнения, памяти, SQL-запросах, логах, сессии и окружении.
- **Logger** — PSR-3 совместимый логгер, записывающий сообщения в файлы.
- **Errors** — обработчик ошибок, преобразующий исключения в пользовательские страницы (404, 500 и т.д.).

## Жизненный цикл приложения

1. **Точка входа** — `htdocs/index.php` загружает `architect/bootstrap.php`.
2. **Инициализация окружения** — `EnvironmentManager` определяет окружение, загружает конфигурацию.
3. **Создание контейнера** — `Container` регистрирует сервисы через `ServiceProvider`.
4. **Запуск фреймворка** — `Framework::run()` выполняет statement-ы.
5. **Statement-ы** (последовательность):
   - `core_preinit` — предварительная инициализация.
   - `core_init` — инициализация ядра, регистрация сервисов.
   - `core_load` — загрузка приложения, роутинг.
   - `core_post_load` — после загрузки.
   - `app_load` — загрузка данных модуля.
   - `app_data` — обработка данных (модель).
   - `app_output` — вывод (контроллер).
   - `render` — рендеринг представления.
6. **Обработка запроса** — роутер определяет маршрут, запускается соответствующий контроллер.
7. **Рендеринг** — шаблонизатор (Blueprint) генерирует HTML, который отправляется клиенту.

## Взаимодействие компонентов

```
Запрос → index.php → bootstrap.php → EnvironmentManager → Container → ServiceProvider → Framework → Statement → Router → Controller → Model → View → Blueprint → Ответ
```

## Расширяемость

Фреймворк разработан с учётом расширяемости. Вы можете:
- Создавать собственные сервисы и регистрировать их в `ServiceProvider`.
- Добавлять новые statement-ы и hooks.
- Разрабатывать Composer-пакеты (Packages) и подключать их через `architect/Packages/`.
- Интегрировать сторонние библиотеки через контейнер.

## Заключение

Architect RED 2 предлагает современную, модульную архитектуру, которая подходит как для небольших проектов, так и для крупных enterprise-приложений. Благодаря statement-based подходу, DI-контейнеру и поддержке нескольких приложений фреймворк обеспечивает гибкость, производительность и удобство разработки.
