# Маршрутизатор (Router)

Маршрутизатор – компонент, отвечающий за сопоставление HTTP-запросов с контроллерами и действиями. Architect RED 2 использует декларативную JSON-конфигурацию маршрутов и поддерживает автоматическое разрешение (auto‑resolution) на основе структуры модулей.

## Конфигурация маршрутов

Маршруты определяются в JSON-файлах внутри папки `app/routes/`. Имя файла может быть любым, но рекомендуется называть его в соответствии с логической группой маршрутов (например, `home.json`, `api.json`).

### Структура маршрута

```json
{
    "route": "/about",
    "controller": "About\\AboutController",
    "methods": ["GET"],
    "middleware": ["auth"],
    "params": {
        "__template": "special"
    }
}
```

- **route** – шаблон URL (может содержать параметры `{param}`).
- **controller** – полное имя класса контроллера (с пространством имён).
- **methods** – массив разрешённых HTTP-методов (GET, POST, PUT, DELETE и т.д.).
- **middleware** – список middleware, которые будут выполнены перед контроллером.
- **params** – дополнительные параметры, передаваемые в контекст маршрута (например, настройки шаблона).

### Параметры в маршруте

Параметры обозначаются фигурными скобками:

```json
{
    "route": "/user/{id}/profile",
    "controller": "User\\ProfileController"
}
```

Значение параметра будет доступно в контроллере как аргумент метода с тем же именем:

```php
public function show(int $id) { ... }
```

### Автоматическое разрешение (Auto‑resolution)

Если маршрут не указан явно, Router пытается определить контроллер и действие на основе URL. Правила авторазрешения:

```
URL: /module/controller/action
Соответствует: App\Modules\<Module>\<Controller>Controller::action()
```

Например, запрос `/blog/post/list` вызовет `App\Modules\Blog\PostController::list()`.

Авторазрешение можно отключить в конфигурации `app/config/router.json`:

```json
{
    "auto_resolution": false
}
```

## Загрузка маршрутов

Маршруты загружаются при инициализации приложения (на этапе `core_init`). Router сканирует все JSON-файлы в `app/routes/` и объединяет их.

### Порядок загрузки

1. Загружаются маршруты из основного приложения (если определено несколько приложений, загружаются маршруты текущего).
2. Маршруты из общих модулей (global modules) добавляются с более низким приоритетом.
3. Если есть конфликт (одинаковый шаблон и метод), побеждает первый загруженный маршрут.

## Класс Router

Основной класс – `Architect\Services\Routing\Router`. Он предоставляет следующие методы:

### `match(Request $request): ?Route`

Сопоставляет запрос с загруженными маршрутами и возвращает объект `Route` или `null`, если совпадения нет.

### `getCurrentRoute(): ?Route`

Возвращает текущий обработанный маршрут.

### `getParam(string $key): mixed`

Возвращает дополнительный параметр маршрута (из поля `params`).

### `generate(string $name, array $parameters = []): string`

Генерирует URL по имени маршрута (если маршруты именованы). В текущей реализации имена не поддерживаются, но метод зарезервирован.

## Объект Route

Содержит информацию о совпавшем маршруте:

- `controller` – класс контроллера
- `action` – имя действия (если не указано, используется `index`)
- `parameters` – извлечённые из URL параметры
- `middleware` – список middleware
- `config` – исходная конфигурация маршрута

## Middleware в маршрутах

Middleware выполняются до вызова контроллера и могут модифицировать запрос или ответ. Middleware указываются в виде строковых идентификаторов, которые резолвятся через `MiddlewareResolver`.

Пример:

```json
{
    "route": "/admin",
    "controller": "Admin\\DashboardController",
    "middleware": ["auth", "role:admin"]
}
```

## Интеграция с приложениями (Apps)

Architect поддерживает несколько приложений в одном экземпляре фреймворка. Каждое приложение может иметь свою папку маршрутов (`app/routes/` внутри папки приложения). Router загружает маршруты из активного приложения, определённого через `Apps` сервис.

## Отладка маршрутизации

Debug Panel содержит вкладку **Routing**, где отображаются все загруженные маршруты, их параметры и совпадение с текущим запросом.

Также можно логировать процесс маршрутизации, установив в конфигурации логгера уровень `debug` для канала `routing`.

## Расширение Router

Вы можете заменить стандартный Router собственным реализациями, зарегистрировав свой класс в контейнере под идентификатором `router`. Однако это требует глубокого понимания внутренней работы фреймворка.

## Примеры

### Простой маршрут

```json
{
    "route": "/",
    "controller": "Home\\HomeController",
    "methods": ["GET"]
}
```

### Маршрут с несколькими методами

```json
{
    "route": "/api/users",
    "controller": "Api\\UserController",
    "methods": ["GET", "POST", "PUT"]
}
```

### Маршрут с параметрами и middleware

```json
{
    "route": "/post/{slug}/edit",
    "controller": "Post\\EditController",
    "methods": ["GET", "POST"],
    "middleware": ["auth", "csrf"]
}
```

## Заключение

Маршрутизатор Architect RED 2 сочетает простоту декларативной конфигурации с гибкостью автоматического разрешения. Используйте JSON-файлы для явного определения маршрутов и middleware для добавления слоёв логики.

Дополнительные сведения см. в [документации по маршрутизации](../docs2/routing.md).
