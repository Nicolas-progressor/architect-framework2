# Интернационализация (I18n)

Компонент I18n обеспечивает поддержку многоязычности в приложении, позволяя переводить текстовые строки, форматировать даты, числа и валюты в соответствии с локалью пользователя. Architect RED 2 использует JSON-файлы для хранения переводов и предоставляет простой API для работы с ними.

## Конфигурация

Настройки интернационализации находятся в `app/config/lang.json`:

```json
{
    "default": "ru",
    "supported": ["ru", "en", "de"],
    "fallback": "en",
    "auto_detect": true,
    "store": "session",
    "domain": "messages"
}
```

- `default` – язык по умолчанию.
- `supported` – список поддерживаемых языков.
- `fallback` – язык, используемый если перевод для текущего языка отсутствует.
- `auto_detect` – автоматически определять язык из заголовка `Accept-Language`.
- `store` – где хранить выбранный язык (`session`, `cookie`, `url`).
- `domain` – домен переводов (используется для группировки файлов).

## Структура файлов переводов

Переводы хранятся в папке `app/lang/` в подпапках, названных по коду языка:

```
app/lang/
├── ru/
│   ├── messages.json
│   └── validation.json
├── en/
│   ├── messages.json
│   └── validation.json
└── de/
    └── messages.json
```

Каждый JSON-файл содержит пары ключ-значение:

```json
{
    "welcome": "Добро пожаловать",
    "user.profile": "Профиль пользователя",
    "buttons.save": "Сохранить"
}
```

## Использование

### Получение экземпляра

Сервис языка доступен через контейнер:

```php
$lang = $container->get('language');
```

Или через контроллер:

```php
$translation = $this->lang->get('messages.welcome');
```

### Перевод строк

```php
echo $lang->trans('messages.welcome'); // Добро пожаловать
echo $lang->trans('validation.required', ['attribute' => 'email']); // Поле email обязательно.
```

Если перевод не найден, возвращается ключ или значение из fallback-языка.

### Плейсхолдеры

Переводы могут содержать плейсхолдеры, которые заменяются переданными значениями:

```json
{
    "greeting": "Привет, :name!"
}
```

```php
echo $lang->trans('greeting', ['name' => 'Иван']); // Привет, Иван!
```

### Множественное число

Компонент поддерживает множественное число через правило `plural`. В JSON-файле можно определить формы:

```json
{
    "apples": "{0} Нет яблок|{1} Одно яблоко|[2,4] :count яблока|[5,*] :count яблок"
}
```

Использование:

```php
echo $lang->choice('apples', 0); // Нет яблок
echo $lang->choice('apples', 1); // Одно яблоко
echo $lang->choice('apples', 3); // 3 яблока
echo $lang->choice('apples', 10); // 10 яблок
```

## Определение текущего языка

### Автоопределение

Если `auto_detect` включён, язык определяется из заголовка `Accept-Language` браузера. Если язык не поддерживается, используется `default`.

### Ручное переключение

```php
$lang->setLocale('en');
```

Изменение языка сохраняется в сессии или куке (в зависимости от настройки `store`).

### Получение текущего языка

```php
$current = $lang->getLocale(); // 'ru'
```

## Маршрутизация с языковым префиксом

Architect поддерживает языковые префиксы в URL (например, `/en/about`, `/ru/about`). Для этого нужно настроить маршруты с параметром `{lang}`.

Пример маршрута:

```json
{
    "route": "/{lang}/about",
    "controller": "AboutController",
    "constraints": {
        "lang": "ru|en|de"
    }
}
```

В контроллере можно установить язык на основе параметра:

```php
public function __construct(Language $lang)
{
    $this->lang = $lang;
}

public function about(string $lang)
{
    $this->lang->setLocale($lang);
    // ...
}
```

## Форматирование дат и чисел

Компонент Language предоставляет методы для форматирования в соответствии с локалью:

```php
$date = $lang->formatDate('2026-03-14'); // 14.03.2026 (для ru)
$time = $lang->formatTime('14:30:00'); // 14:30
$number = $lang->formatNumber(1234.567, 2); // 1 234,57
$currency = $lang->formatCurrency(99.99, 'USD'); // 99,99 $ (зависит от локали)
```

Для работы с форматированием требуется установка расширения PHP `intl`. Если оно отсутствует, используются fallback-форматы.

## Загрузка переводов из других источников

По умолчанию переводы загружаются из JSON-файлов. Вы можете реализовать собственный загрузчик, реализовав `TranslationLoaderInterface`, и зарегистрировать его в контейнере.

```php
use Architect\Services\I18n\Contracts\TranslationLoaderInterface;

class DatabaseLoader implements TranslationLoaderInterface
{
    public function load(string $locale, string $domain): array
    {
        // загрузить переводы из БД
    }
}
```

## Интеграция с шаблонизатором

### В PHP-шаблонах

Используйте глобальную функцию `__()` (если зарегистрирована) или обращайтесь к сервису.

```php
<h1><?= $this->lang->trans('title') ?></h1>
```

### В Blueprint

Blueprint предоставляет фильтр `trans` и функцию `__`:

```blade
<h1>{{ 'title' | trans }}</h1>
<p>{{ __('messages.welcome') }}</p>
```

## Примеры

### Простое использование

```php
// Установка языка
$lang->setLocale('en');

// Перевод
echo $lang->trans('messages.hello'); // Hello

// С плейсхолдером
echo $lang->trans('user.greeting', ['name' => 'John']); // Hello, John!
```

### Многоязычный маршрут

```php
// Маршрут: /{lang}/contact
public function contact(string $lang)
{
    $this->lang->setLocale($lang);
    return $this->view('contact', [
        'title' => $this->lang->trans('pages.contact')
    ]);
}
```

### Форматирование в шаблоне

```php
<p><?= $lang->formatDate($post['created_at']) ?></p>
<p><?= $lang->formatNumber($post['views']) ?> просмотров</p>
```

## Заключение

Компонент I18n предоставляет полный набор инструментов для создания многоязычных приложений, включая переводы, плюрализацию, форматирование и поддержку языковых префиксов в URL. Его интеграция с шаблонизаторами и контейнером зависимостей делает использование простым и эффективным.

Дополнительные сведения см. в [документации по интернационализации](../docs2/i18n.md).
