### Концепция дебаг‑панели (в нижней части экрана)

#### Общее описание

Дебаг‑панель располагается в нижней части окна браузера в виде компактной горизонтальной полосы. Она всегда видна в режиме разработки и автоматически скрывается в продакшене. Панель содержит набор кнопок‑столбцов, каждая из которых отображает ключевую метрику и при клике открывает всплывающее окно с детализированной информацией.

Включается и настраивается в конфиге: app\config\debug.json

#### Визуальный дизайн основной панели


* **Расположение:** фиксированная позиция у нижнего края экрана (`position: fixed; bottom: 0; left: 0; right: 0;`).
* **Высота:** $30\ \text{px}$.
* **Фон:** градиент от тёмно‑серого ($\#333$) до чёрного ($\#000$).
* **Граница:** тонкая светлая линия сверху ($1\ \text{px}$ solid $\#444$).
* **Текст:** белый, шрифт без засечек, очень мелкий ($8–9\ \text{pt}$).
* **Разделители:** тонкие вертикальные линии светло‑серого цвета между кнопками.

#### Кнопки‑столбцы основной панели

Каждый столбец — это кнопка с иконкой и кратким текстовым индикатором. При наведении курсора появляется всплывающая подсказка с полным названием.

1. **Время выполнения (Time)**
    * **Иконка:** секундомер (⏱️).
    * **Индикатор:** общее время выполнения запроса в миллисекундах (например, `$142\ \text{ms}$`).
    * **Цвет:** зелёный, если время < $100\ \text{ms}$, жёлтый — $100–500\ \text{ms}$, красный — > $500\ \text{ms}$.
    * **Подсказка:** «Время выполнения запроса».

2. **Память (Memory)**
    * **Иконка:** микросхема RAM (💾).
    * **Индикатор:** пиковое использование памяти в МБ (например, `$4{,}2\ \text{MB}$`).
    * **Цвет:** зелёный, если использование < $50\%$ от `memory_limit`, жёлтый — $50–80\%$, красный — > $80\%$.
    * **Подсказка:** «Использование памяти».

3. **SQL‑запросы (Database)**
    * **Иконка:** цилиндр базы данных (🗄️).
    * **Индикатор:** количество выполненных SQL‑запросов (например, `$7$`).
    * **Цвет:** серый, становится красным, если есть запросы, выполнявшиеся дольше $100\ \text{ms}$.
    * **Подсказка:** «SQL‑запросы».

4. **Ошибки и логи (Logs)**
    * **Иконка:** восклицательный знак в треугольнике (⚠️).
    * **Индикатор:** суммарное количество записей уровня `warning` и `error` (например, `$2$`).
    * **Цвет:** серый — нет предупреждений/ошибок, жёлтый — `warning`, красный — `error`.
    * **Подсказка:** «Ошибки и предупреждения».

5. **Кеш (Cache)**
    * **Иконка:** значок кеша (🔁).
    * **Индикатор:** соотношение хитов к миссам (например, `hit:8/miss:2`).
    * **Цвет:** зелёный при высоком соотношении хитов, красный при преобладании миссов.
    * **Подсказка:** «Статистика кеша».

6. **Сессия (Session)**
    * **Иконка:** отпечаток пальца (🖐️).
    * **Индикатор:** количество переменных в сессии (например, `$5$`).
    * **Цвет:** всегда нейтральный (синий или серый).
    * **Подсказка:** «Данные сессии».

7. **Окружение (Environment)**
    * **Иконка:** шестерёнка (⚙️).
    * **Индикатор:** название текущего окружения (`dev`, `test` и т. д.).
    * **Цвет:** жёлтый для `dev`, зелёный для `test`, красный для `prod` (чтобы предупредить о включённой панели в продакшене).
    * **Подсказка:** «Текущее окружение».

---

#### Всплывающая панель отладки

Открывается по клику на любой из столбцов основной панели. Располагается над ней, занимая нижнюю треть экрана. Имеет единый дизайн для всех модулей.

**Общие элементы всплывающей панели:**

* **Заголовок:** название модуля (например, «SQL‑запросы») и кнопка закрытия (×) справа.
* **Фильтр:** поле поиска и фильтры по параметрам (например, для SQL — «медленные запросы», «SELECT», «INSERT»).
* **Сортировка:** возможность сортировки данных (по времени, по размеру и т. д.).
* **Кнопка «Обновить»:** принудительное обновление данных.
* **Кнопка «Экспорт»:** выгрузка данных в формате JSON или CSV.
* **Область контента:** основная область с детализированной информацией, специфичной для модуля.
* **Нижний колонтитул:** краткая справка по использованию панели и версия дебаг‑инструмента.

**Содержимое всплывающих окон по модулям**

1. **Time (Время)**
    * Таблица с этапами выполнения: «Инициализация», «Загрузка конфигурации», «Выполнение контроллера», «Рендеринг шаблона» и т. д.
    * Столбцы: «Этап», «Начало (мс)», «Длительность (мс)».
    * Визуальная шкала (timeline) внизу.

2. **Memory (Память)**
    * График использования памяти в течение запроса.
    * Данные: «Пиковая память», «Текущая память», «Лимит памяти», «Использовано (%)».
    * Список самых «тяжёлых» переменных (если доступно).

3. **Database (База данных)**
    * Табличный список всех SQL‑запросов.
    * Столбцы: «#», «Запрос», «Время (мс)», «Параметры», «EXPLAIN».
    * Подсветка строк с временем > $100\ \text{ms}$.
    * Возможность развернуть строку для просмотра полного текста запроса и результата EXPLAIN.

4. **Logs (Логи)**
    * Построчное отображение логов.
    * Цвета строк: серый (`debug`), синий (`info`), жёлтый (`warning`), красный (`error`).
    * Столбцы: «Время», «Уровень», «Сообщение», «Файл:Строка».
    * Ссылки на файлы в IDE (если настроено).

5. **Cache (Кеш)**
    * Статистика: «Всего операций», «Хиты», «Миссы», «Hit ratio (%)».
    * Таблица операций кеша: «Ключ», «Действие» (`get`/`set`), «Время (мс)».

6. **Session (Сессия)**
    * Деревовидная структура данных сессии.
    * Отображение типа и значения каждой переменной.
    * Возможность поиска по ключам.

7. **Environment (Окружение)**
    * Полный список переменных окружения (`$_ENV`).
    * Конфигурация приложения (выборочно).
    * Версия PHP, фреймворка и дебаг‑панели.

#### Взаимодействие и поведение

* **Открытие:** клик по столбцу основной панели открывает соответствующую всплывающую панель.
* **Закрытие:** клик по кнопке ×, клик вне панели или клавиша `Esc`.
* **Переключение модулей:** можно открыть один модуль, затем кликнуть на другой столбец — содержимое всплывающей панели обновится без закрытия.
* **Автообновление:** панель может автоматически обновляться каждые $2–3$ секунды (опционально, с тумблером «Авто»).
* **Минимизация:** кнопка «Свернуть» в углу сворачивает всплывающую панель до тонкой полоски с заголовком, позволяя быстро вернуть её.

#### Безопасность и производительность

* Панель автоматически отключается в окружении `prod`.
* Доступ возможен только с IP‑адресов из белого списка (настраивается).
* Все чувствительные данные (пароли, токены) маскируются перед выводом.
* Сбор данных оптимизирован: используется буферизация и ленивая загрузка тяжёлых модулей.

### Дополнение концепции: возможность добавления данных из любой точки кода приложения

#### Механизм добавления пользовательских данных

Для внесения отладочной информации из любой части приложения (контроллеров, моделей, сервисов, хелперов и т. д.) вводится глобальный сервис `DebugDataCollector`.

**Способы доступа к сборщику данных:**

1. **Dependency Injection** — внедрение через конструктор класса (рекомендуемый способ).
2. **Глобальный фасад** — статический метод `Debug::collector()` для быстрого доступа из любого места кода.
3. **Сервис‑локатор** — получение через контейнер зависимостей: `$container->get('debug.collector')`.

#### Методы DebugDataCollector

* `addMessage(string $category, string $message, string $level = 'info', array $context = [])` — добавляет сообщение с контекстом.
* `startTimer(string $name, string $category = 'performance')` — начинает замер времени.
* `stopTimer(string $name)` — останавливает замер и сохраняет результат.
* `addData(string $category, array|object $data, string $description = '')` — добавляет структурированные данные с описанием.
* `incrementCounter(string $category, string $counterName, int $value = 1)` — увеличивает счётчик.
* `markEvent(string $eventName, array $metadata = [])` — отмечает событие с метаданными.
* `setMetadata(string $key, mixed $value)` — устанавливает глобальные метаданные запроса.

#### Новая кнопка‑столбец основной панели: «Debug»

* **Иконка:** звёздочка (⭐) или значок отладки (🛠️).
* **Расположение:** крайняя справа в основной панели.
* **Индикатор:** количество категорий данных + общее число сообщений (например, `4 categories, 15 messages`).
* **Цвет:** синий (нейтральный для пользовательских данных). Если есть сообщения уровня `error` — индикатор становится красным.
* **Подсказка:** «Пользовательские данные отладки из приложения».
* **Поведение:**
    * если пользовательских данных нет — кнопка скрыта;
    * при наличии данных — отображается с индикатором;
    * мигает при добавлении новых данных во время выполнения запроса.

#### Всплывающая панель «Debug» с вкладками

Открывается по клику на кнопку «Debug». Располагается над основной панелью, занимает нижнюю треть экрана.

**Вкладки панели:**

1. **Messages (Сообщения)**
    * таблица: «Категория», «Уровень», «Сообщение», «Контекст», «Время»;
    * фильтрация по уровню (`debug`, `info`, `warning`, `error`) и категории;
    * поиск по тексту сообщения и контекстным данным;
    * подсветка строк по уровням: серый (`debug`), синий (`info`), жёлтый (`warning`), красный (`error`).

2. **Timers (Таймеры)**
    * таблица: «Название», «Категория», «Время (мс)», «Статус» (завершён/незавершён);
    * группировка по категориям;
    * график распределения времени выполнения;
    * подсветка таймеров > 100 мс жёлтым цветом.

3. **Data (Структурированные данные)**
    * древовидная структура с возможностью поиска и фильтрации;
    * подсветка изменений между версиями данных;
    * кнопка «Экспорт» для каждой категории (JSON/CSV);
    * возможность развернуть/свернуть сложные объекты.

4. **Counters (Счётчики)**
    * таблица: «Категория», «Счётчик», «Значение», «Динамика»;
    * графики роста счётчиков;
    * сортировка по значению (топ‑5 самых больших счётчиков).

5. **Events (События)**
    * хронология событий с метаданными;
    * визуализация цепочки вызовов;
    * фильтр по типам событий.

6. **Summary (Сводка)**
    * топ‑5 самых долгих таймеров;
    * статистика по уровням сообщений (круговая диаграмма);
    * динамика счётчиков (график);
    * карта вызовов (какие компоненты добавляли данные);
    * общее время сбора пользовательских данных.

**Общие элементы панели «Debug»:**

* **Заголовок:** «Debug — Пользовательские данные» + кнопка закрытия (×).
* **Панель фильтров:** выбор категории, уровня важности, временного диапазона.
* **Кнопка «Обновить»:** принудительное обновление данных (если панель открыта во время выполнения запроса).
* **Кнопка «Очистить»:** сброс всех пользовательских данных текущего запроса.
* **Индикатор состояния:** «Сбор данных активен» / «Сбор данных отключён».
* **Нижний колонтитул:** краткая справка по использованию панели и версия дебаг‑инструмента.

#### Примеры использования в коде

**В модели:**
```php
class Product extends ModelBase
{
    public function calculatePrice(DebugDataCollector $debug): float
    {
        $debug->startTimer('price_calculation', 'business_logic');
        // Логика расчёта
        $debug->addMessage('business_logic', 'Расчёт цены товара', 'info', [
            'product_id' => $this->id,
            'base_price' => $this->basePrice
        ]);
        $debug->stopTimer('price_calculation');
        return $calculatedPrice;
    }
}
```

**В хелпере:**
```php
function formatDate($timestamp, DebugDataCollector $debug)
{
    $debug->incrementCounter('helper_calls', 'format_date');
    $debug->markEvent('date_formatted', ['timestamp' => $timestamp]);
    return date('d.m.Y', $timestamp);
}
```

#### Особенности реализации и безопасности

**Хранение и жизненный цикл:**
* данные хранятся в памяти текущего HTTP‑запроса;
* автоматически очищаются после отправки ответа;
* не сохраняются между запросами.

**Ограничения для производительности:**
* максимальный размер данных на категорию — 1 МБ;
* максимальное количество сообщений — 1000 на запрос;
* ограничение глубины вложенности структур данных — 5 уровней.

**Безопасность:**
* автоматическое отключение в продакшене (`APP_ENV=prod`);
* белый список IP‑адресов для доступа в продакшене;
* маскировка чувствительных данных (пароли, токены, персональные данные);
* логирование доступа к панели отладки.

**Конфигурация:**
* возможность отключения сбора пользовательских данных через конфиг: `debug.collect_custom_data = false`;
* настройка уровней логирования для разных окружений;
* фильтрация категорий данных для отображения.

#### Интеграция с существующими модулями панели

* **Database:** ссылки на связанные пользовательские данные в описании запросов (например, «Запрос вызван из метода `Product::calculatePrice`»).
* **Logs:** интеграция сообщений уровня `error` с контекстом из пользовательских данных (автоматическое добавление контекста ошибки).
* **Time:** отображение таймеров из контроллера/модели в общем таймлайне (с пометкой «Пользовательский таймер»).
* **Exceptions:** автоматическое добавление контекста из пользовательских данных при ошибках (например, значения переменных на момент исключения).
