## Концепция PHP‑шаблонизатора Blueprint с расширением `.blu`

### Название
**Blueprint**

### Расширение файлов
**.blu** 

### Установка
Architect Blueprint устанавливается через Composer:
```json
// composer.json
{
  "require": {
    "blueprint": "^1.0"
  }
}
```

### Ключевые принципы
* **Безопасность по умолчанию**: автоматическое экранирование вывода.
* **Читаемость**: интуитивный синтаксис для дизайнеров и разработчиков.
* **Расширяемость**: простой API для создания фильтров, функций и тегов.
* **Производительность**: компиляция шаблонов в чистый PHP‑код.
* **Изоляция**: шаблоны не имеют прямого доступа к глобальным переменным и суперглобальным массивам (`$_GET`, `$_POST` и т. д.).
* **Дополнительные модули**: можно расширить систему дополнителеьными php модулями
* **поддержка Unit**: система поддерживает Architect Unit

### Синтаксис

#### Основные теги
* `{{ ... }}` — вывод переменной с автоматическим экранированием.
* `{# ... #}` — комментарий (не попадает в итоговый HTML).
* `{% ... %}` — управляющая конструкция (условие, цикл, наследование и т. д.).


#### Примеры использования

**1. Вывод данных**
```Blueprint
<h1>{{ page_title }}</h1>
<p>Привет, {{ user.name }}!</p>
```

**2. Условные операторы**
```Blueprint
{% if user.is_logged_in %}
    <p>Добро пожаловать, {{ user.name }}!</p>
{% elseif user.has_pending_registration %}
    <p>Подтвердите регистрацию.</p>
{% else %}
    <a href="/login">Войти</a>
{% endif %}
```

**3. Циклы**
```Blueprint
<ul>
{% for product in products %}
    <li>
        <a href="{{ product.url }}">{{ product.name }}</a>
        {% if product.discount %}
            <span class="discount">{{ product.price_with_discount }} руб.</span>
            <del>{{ product.original_price }} руб.</del>
        {% else %}
            <span>{{ product.price }} руб.</span>
        {% endif %}
    </li>
{% endfor %}
</ul>
```

**4. Наследование шаблонов (макеты)**

*Базовый шаблон (`layout.blu`):*
```Blueprint
<!DOCTYPE html>
<html>
<head>
    <title>{% block title %}Мой сайт{% endblock %}</title>
</head>
<body>
    <header>...</header>
    <main>
        {% block content %}{% endblock %}
    </main>
    <footer>{% block footer %}&copy; 2023{% endblock %}</footer>
</body>
</html>
```

*Шаблон страницы (`page.blu`):*
```Blueprint
{% extends "layout.blu" %}

{% block title %}{{ page_title }} — Мой сайт{% endblock %}

{% block content %}
    <h1>{{ heading }}</h1>
    {{ content_body|raw }} {# raw — отключение экранирования #}
{% endblock %}
```

**5. Фильтры**
```Blueprint
{{ user.bio | truncate(100) | e }} {# обрезать до 100 символов и экранировать #}
{{ "hello world" | capitalize }} {# "Hello world" #}
{{ price | number_format(2, ',') }} {# форматирование числа #}
```

**6. Макросы (переиспользуемые компоненты)**
```Blueprint
{% macro input(name, value, type="text") %}
    <input type="{{ type }}" name="{{ name }}" value="{{ value }}">
{% endmacro %}

{# Использование #}
{{ input('username', '') }}
{{ input('email', '', 'email') }}
```

### Архитектура и реализация

#### Компоненты
1. **Lexer (лексер)** — разбивает шаблон на токены (`VARIABLE`, `TAG_START`, `STRING` и т. д.).
2. **Parser (парсер)** — преобразует поток токенов в абстрактное синтаксическое дерево (AST).
3. **Compiler (компилятор)** — генерирует PHP‑код из AST.
4. **Runtime (среда выполнения)** — выполняет скомпилированный код, предоставляет функции для фильтров, функций, наследования.
5. **Loader** — загружает шаблоны из файловой системы или других источников (БД, сети).
6. **Cache** — кэширует скомпилированные шаблоны для повышения производительности.

#### Рабочий процесс
1. Пользователь запрашивает шаблон (`view.blu`).
2. `Loader` ищет файл шаблона.
3. Если шаблон скомпилирован и кэширован — загружается готовый PHP‑код. Иначе:
   * `Lexer` → `Parser` → `Compiler` генерируют PHP‑файл.
   * Скомпилированный код сохраняется в кэш.
4. Сгенерированный PHP‑код выполняется с переданными данными.
5. Результат (HTML) возвращается пользователю.

#### API для разработчика

**Инициализация для сторонних систем (не Architect framework)**
```php
$loader = new FileSystemLoader('/path/to/templates');
$cacheDir = '/path/to/cache';

$blueprint = new Blueprint($loader, [
    'cache' => $cacheDir,
    'debug' => true, // включает отладочную информацию
    'autoescape' => true // автоматическое экранирование
]);
```

**Рендеринг**
```php
echo $blueprint->render('page', [
    'page_title' => 'Главная',
    'user' => $currentUser,
    'products' => $productList
]);
```

иными словами $blueprint->render('имя шаблона', [массив параметров передаваемых в шаблон]);

**Краткая инициализация для Architect framework**
debug (Включение отладочной информации), autoescape (автоматическое экранирование), cache (путь кэша), включается в конфигурации blueprint.json
по умолчанию инициализация не требуется, путь по умолчанию в папке blueprints текущего модуля. кэш находится в папке cache/blueprints
если нужен доступ к blueprint файлу в другой папке то вызов идет через метод $blueprint->renderFrom('путь к файлу', [массив параметров передаваемых в шаблон]);

**Добавление фильтра**
```php
$blueprint->addFilter('markdown', function ($text) {
    return \Parsedown::instance()->text($text);
});
```

**Добавление функции**
```php
$blueprint->addFunction('asset', function ($path) {
    return '/static/' . $path . '?v=' . filemtime($path);
});
// В шаблоне: <img src="{{ asset('images/logo.png') }}">
```

**Поддержка системы Unit**

Unit вызываются в шаблоне с помощью `{% unit::<имя Юнита>(аргументы) %}`.

*поддержка unit (`welcome.blu`):*
```Blueprint
    <main>
        {{ unit::Bootstrap('get') }}
    </main>
    <footer>{{ unit::Html('get') }}</footer>
```

### Особенности безопасности
* **Автоматическое экранирование** (XSS‑защита) для `{{ }}`.
* **Опция `raw`** только для доверенного контента.
* **Ограниченный контекст выполнения** — шаблоны не могут вызывать произвольные PHP‑функции.
* **Валидация путей** при использовании `extends` и `include`.

### Производительность
* **Кэширование скомпилированных шаблонов** на диске.
* **Ленивая компиляция** — шаблон компилируется только при первом обращении.
* **Оптимизация AST** — удаление неиспользуемых блоков, упрощение выражений.

## Концепция PHP‑шаблонизатора Blueprint с расширением `.blu` и поддержкой модулей

### Система модулей Blueprint

Модули — отдельные пакеты, добавляющие в Blueprint новые фильтры, функции, теги, макросы или целые блоки функциональности.

#### Принципы работы с модулями
* **Изолированность**: каждый модуль работает независимо.
* **Гибкость подключения**: модули можно подключать/отключать без правки кода ядра.
* **Версионирование**: поддержка версий модулей для совместимости.
* **Зависимости**: модули могут зависеть от других модулей.
* **Приоритет**: возможность настройки приоритета выполнения модулей.

---

### Типы модулей

1. **Фильтровальные модули** — добавляют новые фильтры для обработки данных:
   * форматирование дат;
   * работа с валютами;
   * текстовые трансформации.

2. **Функциональные модули** — предоставляют новые функции для шаблонов:
   * генерация URL;
   * работа с медиа‑файлами;
   * интеграция с API.

3. **Теговые модули** — вводят новые управляющие конструкции:
   * кастомные циклы;
   * специализированные условия;
   * структурные теги.

4. **UI‑модули** — содержат готовые компоненты интерфейса:
   * кнопки, формы, карточки;
   * навигационные элементы;
   * модальные окна.

5. **Интеграционные модули** — обеспечивают связь с внешними системами:
   * CMS;
   * CRM;
   * платёжные шлюзы.

---

### API для разработки модулей

Базовый интерфейс модуля:
```php
interface BlueprintModuleInterface
{
    public function getName(): string;
    public function getVersion(): string;
    public function getDependencies(): array;
    public function register(Blueprint $engine): void;
}
```

#### Пример создания модуля

Модуль для работы с датами (`DateModule`):
```php
class DateModule implements BlueprintModuleInterface
{
    public function getName(): string
    {
        return 'date';
    }

    public function getVersion(): string
    {
        return '1.0.0';
    }

    public function getDependencies(): array
    {
        return [];
    }

    public function register(Blueprint $engine): void
    {
        // Добавляем фильтры
        $engine->addFilter('format_date', function ($timestamp, $format = 'd.m.Y') {
            return (new DateTime())->setTimestamp($timestamp)->format($format);
        });

        $engine->addFilter('time_ago', function ($timestamp) {
            $diff = time() - $timestamp;
            if ($diff < 60) return 'только что';
            if ($diff < 3600) return floor($diff / 60) . ' мин назад';
            // ...
        });

        // Добавляем функцию
        $engine->addFunction('current_year', function () {
            return date('Y');
        });
    }
}
```

### Управление модулями

#### Регистрация модулей
```php
$blueprint = new Blueprint($loader, $config);

// Регистрация отдельных модулей
$blueprint->registerModule(new DateModule());
$blueprint->registerModule(new MarkdownModule());

// Пакетная регистрация
$modules = [
    new DateModule(),
    new MarkdownModule(),
    new AssetModule()
];
$blueprint->registerModules($modules);
```

#### Конфигурация модулей через файл `blueprint.json`
```json
{
  "modules": {
    "date": {
      "enabled": true,
      "config": {
        "default_format": "d.m.Y H:i"
      }
    },
    "markdown": {
      "enabled": true
    },
    "asset": {
      "enabled": false
    }
  },
  "autoload": [
    "App\\Modules\\*"
  ]
}
```

#### Загрузка модулей из конфигурации
```php
$config = json_decode(file_get_contents('blueprint.json'), true);
$blueprint->loadModulesFromConfig($config);
```

---

### Встроенные модули Blueprint

По умолчанию поставляются следующие модули:

1. **`CoreModule`** — базовая функциональность:
   * стандартные фильтры (`upper`, `lower`, `length`);
   * базовые функции (`range`, `cycle`);
   * основные теги (`for`, `if`, `block`).

2. **`TextModule`** — текстовые операции:
   * `truncate` — обрезка текста;
   * `nl2br` — замена переносов строк на `<br>`;
   * `replace` — поиск и замена.

3. **`NumberModule`** — работа с числами:
   * `number_format` — форматирование чисел;
   * `abs` — модуль числа;
   * `round` — округление.

4. **`AssetModule`** — управление ресурсами:
   * `asset()` — генерация URL для статических файлов;
   * `version()` — добавление версии к URL.

5. **`DebugModule`** — отладочные инструменты:
   * `dump()` — вывод структуры данных;
   * `debug_bar` — панель отладки.

### Механизм разрешения зависимостей

Blueprint автоматически проверяет зависимости модулей:
```php
class BlogModule implements BlueprintModuleInterface
{
    public function getDependencies(): array
    {
        return [
            'date' => '>=1.0',  // модуль date версии 1.0 и выше
            'asset' => '*'       // любой версии модуля asset
        ];
    }

    // ...
}
```

При регистрации система:
1. Проверяет наличие всех зависимостей.
2. Загружает модули в правильном порядке.
3. Выдает ошибку, если зависимость не удовлетворена.

### Кэширование скомпилированных модулей

Для производительности:
* скомпилированный код модулей кэшируется вместе с шаблонами;
* при изменении версии модуля кэш инвалидируется;
* возможна предварительная компиляция всех модулей.

```php
// Включение кэширования модулей
$config['cache_modules'] = true;
$config['module_cache_dir'] = '/path/to/module/cache';
```

## Отладочная информация в шаблонизаторе Blueprint (.blu)


Добавляю раздел о механизмах отладки — они помогут разработчикам быстро находить и исправлять ошибки в шаблонах и модулях.


### Режимы отладки


Blueprint поддерживает три режима отладки:

1. **Выключено** (`debug = false`) — никакой отладочной информации, максимальная производительность.
2. **Стандартный** (`debug = true`) — базовая информация об ошибках и предупреждениях.
3. **Подробный** (`debug_level = 'verbose'`) — полная трассировка выполнения шаблонов.

**Настройка:**
```php
$blueprint = new Blueprint($loader, [
    'debug' => true,
    'debug_level' => 'verbose', // или 'basic'
    'show_errors' => true
]);
```

### Компоненты отладочной системы

#### 1. Отладочные теги в шаблонах
Специальные теги для вывода отладочной информации прямо в шаблоне:

```twig
{# Вывод структуры переменной #}
{{ dump(user) }}

{# Вывод всех доступных переменных в контексте #}
{{ dump() }}

{# Проверка условий с отладкой #}
{{ debug_if(user.is_admin, 'Пользователь — администратор') }}

{# Трассировка выполнения #}
{{ debug_trace('Достигнут блок заголовка') }}
```

#### 2. Панель отладки (Debug Bar) (не Architect Framework)
Автоматически добавляется в конец страницы при включённом режиме отладки. Показывает:
* время рендеринга шаблона;
* список загруженных модулей;
* использованные переменные;
* цепочку наследования шаблонов;
* статистику вызовов фильтров и функций.

Пример отображения:
```html
<div class="blueprint-debug-bar">
    <strong>Blueprint Debug</strong>
    <p>Шаблон: <code>page.blu</code></p>
    <p>Время рендеринга: <span>12ms</span></p>
    <p>Модули: <span>date, markdown, asset</span></p>
    <p>Переменные: <span>page_title, user, products (3)</span></p>
</div>
```

#### 2.1 Панель отладки (Debug Bar) (Architect Framework)
Для Architect Framework используется стандартный сервис отладки Debug.
В него добавляется столбец Blueprint

#### 3. Логирование ошибок (не Architect Framework)
Blueprint может записывать ошибки в лог‑файл:
```php
$blueprint->setLogger(new FileLogger('/path/to/blueprint.log'));
```
В лог записываются:
* синтаксические ошибки шаблонов;
* ошибки выполнения фильтров;
* проблемы с наследованием шаблонов;
* предупреждения о небезопасном коде.

#### 3.1 Логирование ошибок (ДЛЯ Architect Framework)
В Architect Framework Blueprint использует стандартный сервис Logger.

**Пример записи в логе:**
```
[2023-10-05 14:30:25] ERROR: Синтаксическая ошибка в шаблоне 'page.blu' на строке 15:
Ожидалось 'endif', найдено 'endfor'
[2023-10-05 14:30:26] WARNING: Переменная 'user.profile' не определена в шаблоне 'header.blu'
```

#### 4. Валидатор шаблонов
Инструмент для проверки шаблонов перед деплоем:
```bash
php vendor/bin/blueprint validate templates/
```
Проверяет:
* корректность синтаксиса;
* соответствие открывающих/закрывающих тегов;
* наличие всех наследуемых шаблонов;
* существование переменных, используемых в `{{ }}`.

#### 5. Профилировщик шаблонов
Для анализа производительности:
```php
$profiler = new TemplateProfiler();
$blueprint->setProfiler($profiler);

// После рендеринга
$stats = $profiler->getStats();
print_r($stats);
```
**Выводит статистику:**
* время компиляции каждого шаблона;
* количество вызовов функций/фильтров;
* использование памяти;
* «горячие точки» — самые медленные участки.

---

### Обработка ошибок

Blueprint перехватывает и форматирует ошибки с контекстом:

**Пример сообщения об ошибке:**
```
Ошибка в шаблоне "page.blu" (строка 25):

23:     <div class="content">
24:         {{ post.content|markdown|raw }}
25:         {{ user.profile.avatar.url }}
26:     </div>

Ошибка: Неопределённое свойство 'avatar' у объекта 'profile'.
Контекст:
- user: объект User
- profile: null

Возможные решения:
1. Проверить, что профиль пользователя загружен.
2. Добавить проверку: {% if user.profile %}...{% endif %}
3. Использовать оператор null‑coalescing: {{ user.profile?.avatar?.url ?? 'default.png' }}
```

#### Включение отладки

// Базовый режим
$blueprint->enableDebug();

$blueprint->setErrorHandler(function ($error) {

$debugInfo = $blueprint->getDebugInfo();

### Отладочные фильтры и функции

В режиме отладки доступны специальные инструменты:

| Фильтр/Функция | Назначение | Пример использования |
|--------------|-----------|-------------------|
| `dump()` | Вывод структуры переменной | `{{ user|dump }}` |
| `type()` | Определение типа переменной | `{{ post.tags|type }} → array` |
| `debug_info()` | Общая информация о контексте | `{{ debug_info() }}` |
| `trace()` | Добавление метки в трассировку | `{{ trace('Начало цикла товаров') }}` |
| `memory_usage()` | Текущее использование памяти | `{{ memory_usage() }} MB` |

**Пример в шаблоне:**
```twig
{% if debug_mode() %}
    <div class="debug-info">
        <p>Тип данных: {{ data|type }}</p>
        <p>Память: {{ memory_usage() }} MB</p>
        {{ dump(data) }}
    </div>
{% endif %}
```

### Конфигурация отладки

Настройки в `blueprint.json`:
```json
{
  "debug": {
    "enabled": true,
    "level": "verbose",
    "log_file": "/var/log/blueprint.log",
    "show_errors": true,
    "profiling": true,
    "debug_bar": true,
    "allowed_ips": ["127.0.0.1", "192.168.1.*"]
  }
}
```

**Ограничение по IP** — отладочная информация показывается только для указанных адресов (безопасность на продакшене).

---

### Рекомендации по использованию

**В разработке:**
* включить `debug_level = 'verbose'`;
* использовать `dump()` для проверки данных;
* анализировать панель отладки;
* запускать валидатор перед коммитом.

**На продакшене:**
* отключить отладку (`debug = false`);
* настроить логирование ошибок;
* оставить валидатор в CI/CD‑пайплайне.

---

### Преимущества системы отладки Blueprint

* **Контекстные ошибки** — точные указания на строку и проблему.
* **Визуальная панель** — быстрый обзор состояния шаблона.
* **Профилирование** — оптимизация производительности.
* **Валидация** — предотвращение ошибок до запуска.
* **Гибкость** — настройка уровня детализации под задачу.
* **Безопасность** — ограничение доступа к отладке по IP.
