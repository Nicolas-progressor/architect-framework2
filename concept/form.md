### Концепция обработчика форм для PHP MVC фреймворка Architect Framework

**Цель:** создать универсальный обработчик форм, который обеспечит:
* унифицированную работу с формами в рамках фреймворка;
* поддержку чистого HTML и шаблонизатора Architect Blueprint;
* валидацию данных на стороне сервера;
* защиту от CSRF‑атак;
* простую интеграцию в существующие контроллеры и представления.

**Ключевые возможности:**

1. **Поддержка двух режимов генерации форм:**
   * чистый HTML (вручную в шаблонах);
   * через шаблонизатор Architect Blueprint (с использованием вспомогательных методов).
2. **Автоматическая генерация CSRF‑токена** для защиты форм.
3. **Валидация данных** с набором стандартных правил (обязательное поле, email, длина строки и т. д.).
4. **Отображение ошибок валидации** рядом с соответствующими полями формы.
5. **Сохранение введённых данных** при ошибке валидации (чтобы пользователь не вводил всё заново).
6. **Гибкая настройка** через конфигурационные файлы или параметры метода.
7. **Интеграция с моделью данных** (автоматическое заполнение объектов модели из данных формы).

**Архитектура:**
* **FormBuilder** — класс для генерации HTML‑кода полей формы (работает с Blueprint).
* **FormValidator** — класс для проверки данных формы по заданным правилам.
* **FormHandler** — основной класс, координирующий работу FormBuilder и FormValidator, обрабатывающий отправку формы.
* **CSRFTokenManager** — класс для генерации и проверки CSRF‑токенов.

### Техническое задание (ТЗ)

#### 1. Требования к функциональности

**1.1. Генерация форм**
* Поддержка ручного написания HTML‑форм с обязательным включением CSRF‑токена.
* Поддержка генерации форм через Blueprint с использованием методов:
   * `form_open($action, $method = 'POST')` — начало формы;
   * `text_field($name, $value = '', $attributes = [])` — текстовое поле;
   * `email_field($name, $value = '', $attributes = [])` — поле email;
   * `password_field($name, $attributes = [])` — поле пароля;
   * `submit_button($label = 'Отправить')` — кнопка отправки;
   * `form_close()` — закрытие формы.

**1.2. Валидация данных**
* Набор стандартных правил валидации:
   * `required` — обязательное поле;
   * `email` — проверка формата email;
   * `min_length:$n` — минимальная длина строки;
   * `max_length:$n` — максимальная длина строки;
   * `numeric` — числовое значение;
   * `match:$field` — совпадение с другим полем (например, пароль и подтверждение пароля).
* Возможность добавления пользовательских правил валидации.
* Возврат массива ошибок валидации с указанием поля и сообщения об ошибке.

**1.3. Обработка отправки формы**
* Автоматический сбор данных из `$_POST`.
* Проверка CSRF‑токена.
* Запуск валидации по заданным правилам.
* При ошибках — возврат к форме с отображением ошибок и сохранением введённых данных.
* При успешной валидации — выполнение пользовательского обработчика (callback) или возврат данных для дальнейшей обработки.

**1.4. Отображение ошибок**
* Автоматическое отображение ошибок рядом с полями формы (для Blueprint).
* Для чистого HTML — предоставление массива ошибок для ручного отображения.

#### 2. Интерфейс и API

**2.1. Основные классы и методы**

* **FormHandler**
   * `handle($formName, $validationRules, $callback)` — основной метод обработки формы.
   * Параметры:
     * `$formName` — имя формы (используется для CSRF и сохранения данных);
     * `$validationRules` — массив правил валидации;
     * `$callback` — функция, вызываемая при успешной валидации.
   * Возвращает: `true` при успешной обработке, массив ошибок при неудаче.

* **FormBuilder (для Blueprint)**
   * `open($action, $method)` — генерирует `<form>` с CSRF‑токеном.
   * `textField($name, $value, $attrs)` — генерирует `<input type="text">`.
   * `emailField($name, $value, $attrs)` — генерирует `<input type="email">`.
   * `passwordField($name, $attrs)` — генерирует `<input type="password">`.
   * `submitButton($label)` — генерирует кнопку отправки.
   * `close()` — генерирует `</form>`.

* **FormValidator**
   * `validate($data, $rules)` — проверяет данные по правилам.
   * Возвращает массив ошибок или пустой массив, если валидация пройдена.

* **CSRFTokenManager**
   * `generateToken($formName)` — создаёт токен для формы.
   * `validateToken($formName, $token)` — проверяет токен.

**2.2. Формат правил валидации**
```php
$rules = [
    'username' => 'required|min_length:3|max_length:20',
    'email' => 'required|email',
    'password' => 'required|min_length:6',
    'confirm_password' => 'required|match:password'
];
```

#### 3. Пример использования

**3.1. Через Blueprint (в шаблоне)**
```Blueprint  
{{ form_open('/register', 'POST') }}
    {{ text_field('username', old('username'), ['placeholder' => 'Имя пользователя']) }}
    {{ email_field('email', old('email')) }}
    {{ password_field('password') }}
    {{ password_field('confirm_password') }}
    {{ submit_button('Зарегистрироваться') }}
{{ form_close() }}
```

**3.2. В контроллере**
```php
class UserController extends Controller {
    public function register() {
        $handler = new FormHandler();
        $result = $handler->handle('register_form', [
            'username' => 'required|min_length:3',
            'email' => 'required|email',
            'password' => 'required|min_length:6'
        ], function($data) {
            // Сохранение пользователя
            User::create($data);
            return redirect('/success');
        });

        if (is_array($result)) {
            // Ошибки валидации
            return view('register', ['errors' => $result]);
        }
    }
}
```

#### 4. Требования к безопасности
* Обязательная проверка CSRF‑токена для всех POST‑запросов форм.
* Экранирование данных при выводе в HTML (защита от XSS).
* Фильтрация и валидация всех входящих данных.

#### 5. Требования к производительности
* Минимизация количества операций при генерации форм.
* Кэширование CSRF‑токенов на время сессии.

#### 6. Документация
* Подробное описание API для каждого класса и метода.
* Примеры использования для чистого HTML и Blueprint.
* Руководство по добавлению пользовательских правил валидации.

#### 7. Тестирование
* Юнит‑тесты для FormValidator (проверка всех правил валидации).
* Интеграционные тесты для FormHandler (обработка успешных и ошибочных сценариев).
* Тесты безопасности (проверка CSRF, XSS).

**Критерии приёмки:**
* Обработчик корректно генерирует формы через Blueprint и работает с чистым HTML.
* Валидация данных выполняется по заданным правилам, ошибки отображаются корректно.
* CSRF‑защита предотвращает подделки запросов.
* Введённые данные сохраняются при ошибке валидации.
* Код покрыт тестами (не менее 80 % покрытия).
* Документация полная и понятная.
