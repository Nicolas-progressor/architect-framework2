### Техническое задание: система определения окружения (Environment System) для PHP MVC‑фреймворка Architect Framework

#### 1. Цель

Реализовать систему определения окружения, обеспечивающую гибкое управление настройками приложения в зависимости от среды выполнения (разработка, тестирование, продакшн и т. д.) с использованием JSON‑конфигураций.

#### 2. Требования

**Функциональные:**

* определение текущего окружения в строгой последовательности источников;
* загрузка конфигурационных настроек из JSON‑файлов;
* объединение общих и специфических настроек окружения;
* безопасный доступ к настройкам по ключу;
* вспомогательные методы для проверки типа окружения.

**Нефункциональные:**

* высокая производительность (загрузка конфигурации один раз при старте);
* безопасность (чувствительные данные не хранятся в коде);
* простота развёртывания и масштабирования;
* удобство поддержки и расширения.

#### 3. Окружения

Поддерживаемые окружения:

* `development` — разработка;
* `testing` — тестирование;
* `staging` — предпродакшн;
* `production` — продакшн.

#### 4. Структура конфигурации

```
app/
└── config/
    ├── config.json          # общие настройки для всех окружений
    └── environment/         # папка с настройками для конкретных окружений
        ├── development.json
        ├── testing.json
        ├── staging.json
        └── production.json
```

**Формат JSON‑файлов:**

```json
{
  "database": {
    "host": "localhost",
    "name": "myapp_dev",
    "user": "dev_user",
    "password": "secret"
  },
  "debug": true,
  "error_reporting": "E_ALL",
  "cache": {
    "driver": "file",
    "path": "/tmp/cache"
  }
}
```

#### 5. Механизм определения окружения

Порядок определения (первое найденное значение используется):

1. Переменная окружения ОС `APP_ENV`.
2. Файл `.env` в корне проекта (формат «ключ=значение»).
3. Константа PHP `APP_ENV`, заданная в конфигурационном файле.
4. Значение по умолчанию — `production`.

#### 6. Класс `EnvironmentManager`

**Назначение:** центральный компонент системы, отвечающий за:

* определение текущего окружения;
* загрузку и парсинг JSON‑конфигураций;
* объединение настроек;
* предоставление доступа к настройкам.

**Методы:**

| Метод | Описание | Возвращаемое значение |
|------|---------|-------------------|
| `detectEnvironment(): string` | Определяет окружение по алгоритму выше | Название окружения (`development`, `testing`, `staging`, `production`) |
| `loadConfiguration(): array` | Загружает `config.json` из `app/config/`, затем соответствующий JSON‑файл из `app/config/environment/`, объединяет массивы (специфичные настройки переопределяют общие) | Ассоциативный массив всех настроек |
| `get(string $key, mixed $default = null): mixed` | Безопасный доступ к настройкам по ключу (например, `database.host`) | Значение настройки или `$default`, если ключ не найден |
| `isDevelopment(): bool` | Проверяет, является ли текущее окружение `development` | `true`/`false` |
| `isTesting(): bool` | Проверяет, является ли текущее окружение `testing` | `true`/`false` |
| `isStaging(): bool` | Проверяет, является ли текущее окружение `staging` | `true`/`false` |
| `isProduction(): bool` | Проверяет, является ли текущее окружение `production` | `true`/`false` |

#### 7. Обработка файла `.env`

Файл `.env` (в корне проекта) используется для установки переменных окружения:

```env
APP_ENV=development
APP_DEBUG=true
DB_HOST=localhost
DB_NAME=myapp_dev
DB_USER=root
DB_PASS=
CACHE_DRIVER=file
```

**Правила обработки:**

* строки, начинающиеся с `#`, игнорируются (комментарии);
* пустые строки игнорируются;
* каждая строка в формате `КЛЮЧ=ЗНАЧЕНИЕ`;
* значения устанавливаются в переменные окружения ОС через `putenv()` и `$_ENV`;
* переменные ОС имеют приоритет над `.env`.

#### 8. Интеграция с MVC‑архитектурой

**Этапы интеграции:**

1. Инициализация `EnvironmentManager` на раннем этапе bootstrap‑процесса (до создания роутеров, контроллеров и моделей).
2. Предоставление доступа к настройкам через `EnvironmentManager::get()` для компонентов фреймворка (БД, кэш, логирование, роутинг).
3. Использование методов проверки окружения (`isDevelopment()` и т. д.) для условного включения/выключения функционала.

#### 9. Ожидаемые результаты

**После реализации системы:**

* разработчик может легко переключать окружения через `APP_ENV` или `.env`;
* настройки для разных окружений хранятся в отдельных JSON‑файлах в папке `app/config/environment/`;
* компоненты фреймворка получают актуальные настройки в зависимости от окружения;
* приложение ведёт себя корректно в любой среде (ошибки скрыты в продакшне, детальное логирование в разработке и т. д.).

#### 10. Критерии приёмки

Система считается реализованной, если:

1. Окружение корректно определяется по приоритетной цепочке источников.
2. JSON‑конфигурации из `app/config/` и `app/config/environment/` загружаются и объединяются без ошибок.
3. Доступ к настройкам по ключу работает для вложенных структур.
4. Методы проверки окружения возвращают верные значения.
5. Файл `.env` корректно парсится и устанавливает переменные окружения.
6. Система интегрируется с существующим MVC‑ядром без конфликтов.

### Документация пользователя

#### 1. Настройка окружений

1. Создайте папку `app/config/environment/`, если её нет.
2. Создайте JSON‑файлы для нужных окружений в `app/config/environment/`.
3. Заполните общие настройки в `app/config/config.json`.
4. Укажите специфические настройки в соответствующих файлах окружения в `app/config/environment/`.
5. Установите окружение одним из способов:
   * задайте переменную `APP_ENV` в ОС: `export APP_ENV=development`;
   * создайте файл `.env` в корне проекта с `APP_ENV=development`;
   * определите константу `APP_ENV` в PHP‑коде.

#### 2. Использование в коде

**Инициализация:**

```php
$envManager = new \Architect\Core\EnvironmentManager();
```

**Получение настроек:**

```php
// Получение значения с дефолтом
$dbHost = $envManager->get('database.host');
$debugMode = $envManager->get('debug', false);

// Вложенные ключи
$cachePath = $envManager->get('cache.path');
```

**Проверка окружения:**

```php
if ($envManager->isDevelopment()) {
    // Инициализировать панель отладки
}

if ($envManager->isProduction()) {
    // Включить кэширование
}
```

#### 3. Рекомендации

* не храните чувствительные данные (пароли, API‑ключи) в JSON‑файлах, используйте `.env` или переменные ОС;
* используйте `app/config/config.json` для настроек, общих для всех окружений;
* для новых окружений создайте отдельный JSON‑файл в `app/config/environment/` и укажите его в `APP_ENV`;
* убедитесь, что все JSON‑файлы валидны — используйте валидаторы JSON перед деплоем.
