# План расширения системы для легкой интеграции пакетов

## Проблема
Текущая интеграция пакетов (например, Queue) требует жесткого добавления провайдеров в `bootstrap.php` и путей команд в `bin/arc`, что является костылями и усложняет поддержку.

## Цель
Создать механизм автоматической регистрации сервис-провайдеров из пакетов без ручного редактирования кода ядра.

## Предлагаемое решение

### 1. Формат объявления провайдеров
Пакеты объявляют своих провайдеров в `composer.json` в секции `extra.architect.providers` (уже существует).

Пример:
```json
"extra": {
    "architect": {
        "providers": [
            "Architect\\Queue\\Providers\\QueueServiceProvider"
        ]
    }
}
```

### 2. Кэширование списка провайдеров
- Создать класс `ProviderDiscovery`, который сканирует все установленные пакеты Composer и собирает провайдеры.
- Генерировать файл кэша `bootstrap/cache/providers.php` при установке/обновлении пакетов (через Composer-скрипты).
- Кэш будет содержать массив полных имен классов провайдеров.

### 3. Загрузка провайдеров в bootstrap.php
- Модифицировать `bootstrap.php` для загрузки провайдеров из кэша вместо жесткого кода.
- Использовать `AggregateServiceProvider` для регистрации всех обнаруженных провайдеров.

### 4. Удаление костылей
- Убрать условное добавление `QueueServiceProvider` из `bootstrap.php`.
- Убрать добавление пути команд очереди из `bin/arc`.
- Вместо этого команды будут регистрироваться через `QueueServiceProvider::boot()` (уже реализовано).

### 5. Команда для обновления кэша
- Добавить консольную команду `arc package:discover` для ручного обновления кэша провайдеров.

### 6. Производительность
- Кэширование гарантирует, что сканирование пакетов происходит только при изменении зависимостей Composer.
- При каждом запросе загружается только готовый файл кэша (быстро).

## Преимущества
- Новые пакеты автоматически интегрируются после установки.
- Не требуется редактировать код фреймворка.
- Соответствует принципам Laravel Package Discovery, но легче.
- Минимальные накладные расходы на производительность.

## Недостатки
- Требует добавления Composer-скриптов в корневой `composer.json`.
- Необходимо поддерживать обратную совместимость.

## Следующие шаги
1. Переключиться в режим Code для реализации.
2. Создать класс ProviderDiscovery.
3. Добавить Composer-скрипт для генерации кэша.
4. Модифицировать bootstrap.php.
5. Удалить костыли.
6. Протестировать с пакетами Queue и HttpClient.
