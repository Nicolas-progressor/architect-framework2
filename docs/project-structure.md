# Структура проекта

Понимание структуры проекта Architect RED 2 важно для эффективной разработки. В этом разделе описаны ключевые папки и файлы, их назначение и типичное содержимое.

## Корневая директория

```
architect_framework_2/
├── architect/          # Ядро фреймворка
├── app/                # Приложения и конфигурация
├── htdocs/             # Публичная директория (точка входа)
├── blueprint/          # Шаблонизатор Blueprint (отдельный пакет)
├── axiom/              # ORM Axiom (отдельный пакет)
├── architect/auth-system/ # Система аутентификации (отдельный пакет)
├── docs/               # Документация (устаревшая)
├── docs2/              # Новая пользовательская документация
├── techdocs/           # Техническая документация
├── cache/              # Кэш (генерируется автоматически)
├── storage/            # Файлы приложения (загрузки, временные файлы)
├── vendor/             # Composer зависимости
├── .env                # Переменные окружения
├── .env.example        # Шаблон .env
├── composer.json       # Зависимости проекта
├── composer.lock       # Версии зависимостей
└── README.md           # Описание проекта
```

## Директория htdocs/

Публичная директория, доступная из веб-сервера. Содержит точку входа `index.php` и статические файлы.

```
htdocs/
├── index.php                 # Точка входа
├── .htaccess                 # Правила Apache (если используется)
├── assets/                   # Статические файлы (CSS, JS, изображения)
│   ├── css/
│   ├── js/
│   └── images/
└── uploads/                  # Загруженные пользователями файлы
```

## Директория blueprint/

Отдельный пакет шаблонизатора Blueprint. Содержит движок, документацию и примеры.

```
blueprint/

├── docs/                     # Документация Blueprint
├── examples/                 # Примеры шаблонов

## Директория axiom/

Отдельный пакет ORM Axiom. Содержит конструктор запросов, Entity менеджер и интеграции.

```

## Ключевые файлы

### .env

Файл переменных окружения. Содержит чувствительные данные (пароли, ключи) и настройки, которые могут меняться в зависимости от окружения.

**Важно:** Не коммитьте `.env` в репозиторий. Используйте `.env.example` как шаблон.

### composer.json

Определяет зависимости проекта и autoload-правила.

### app/config/config.json

Общие настройки приложения: название, версия, настройки БД, кэша, сессий, логов.

### app/config/environment/{env}.json

Настройки для конкретного окружения. Переопределяют общие настройки.

### app/config/apps.json

Определяет список приложений и приложение по умолчанию.

### app/config/router.json

Настройки роутера: модуль, контроллер и действие по умолчанию, обработчик 404.

### app/config/debug.json

Конфигурация отладочной панели: включение, категории логов, отображение SQL-запросов и т.д.

## Как добавлять свой код

### Модули

Размещайте модули в `app/apps/{app}/modules/` (для прикладных модулей) или `app/modules/` (для общих модулей). Каждый модуль должен содержать подпапки `controller/`, `model/`, `view/`, `widget/` (опционально), `lang/` (опционально).

### Контроллеры

Контроллеры находятся в `modules/{module}/controller/`. Имя файла должно соответствовать имени контроллера (например, `home.php`). Класс должен наследовать `Architect\Services\Mvc\Controller`.

### Модели

Модели находятся в `modules/{module}/model/`. Имя файла обычно соответствует имени модели (например, `User.php`). Класс должен наследовать `Architect\Services\Mvc\ModelBase`.

### Представления

Представления находятся в `modules/{module}/view/`. Можно использовать обычные PHP-файлы (`.php`) или шаблоны Blueprint (`.blu`). Blueprint рекомендуется для сложных шаблонов.

### Маршруты

Маршруты определяются в JSON-файлах в `app/apps/{app}/routes/` (прикладные) или `app/routes/` (общие). Имя файла может быть любым, но рекомендуется называть его по имени модуля или функциональности.

### Статические хелперы (Statics)

Statics находятся в `architect/Statics/`. Вы можете создавать свои хелперы, добавляя классы в эту директорию и регистрируя их в `Statics.php`.

## Примеры использования
### Консольные команды

Architect RED 2 включает мощную консольную систему, которая позволяет создавать приложения, модули, контроллеры, модели и многое другое через команды CLI. Основной исполняемый файл — `bin/arc`.

Примеры команд:

```bash
# Создать новое приложение
php arc make:app admin

# Создать модуль в приложении home
php arc make:module Products --app=home

# Создать контроллер
php arc make:controller UserController --module=users

# Создать модель
php arc make:model User --module=users

# Создать маршрут
php arc make:route products --app=home --module=products --controller=products --action=index

# Выполнить миграции
php arc db:migrate

# Очистить кэш
php arc cache:clear

# Показать список маршрутов
php arc route:list
```

Подробнее о консольных командах см. [Консоль](console.md).

См. руководство [Создание первого приложения](first-app.md) для практического примера работы со структурой проекта.

## Заключение

Структура проекта Architect RED 2 организована таким образом, чтобы обеспечить чёткое разделение ответственности, простоту навигации и лёгкость расширения. Придерживаясь этой структуры, вы сможете эффективно разрабатывать и поддерживать приложения любого масштаба.
