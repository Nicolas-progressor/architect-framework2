# Логирование

Architect Framework предоставляет мощную систему логирования, совместимую со стандартом PSR-3. Логирование поддерживает каналы, буферизацию, интеграцию с отладочной панелью и гибкую конфигурацию. Логи могут записываться в файлы, отправляться в syslog, базу данных или другие хранилища через плагины.

## Введение

Система логирования Architect построена вокруг сервиса `Logger`, который реализует интерфейс `Psr\Log\LoggerInterface`. Основные возможности:

- **Полная совместимость с PSR-3** – можно использовать любой PSR-3-совместимый логгер.
- **Каналы (channels)** – разделение логов по категориям (app, database, security, etc.).
- **Буферизация** – логи накапливаются в памяти и записываются пачками для повышения производительности.
- **Гибкая конфигурация** – настройка уровней, формата, путей к файлам через JSON-конфигурацию.
- **Интеграция с Debug Panel** – логи автоматически отображаются в отладочной панели.
- **Расширяемость** – возможность добавления собственных писателей (writers) для записи в разные хранилища.

## Конфигурация

### Файл logger.json

Настройки логирования хранятся в `app/config/logger.json`:

```json
{
    "log_dir": null,
    "flush_limit": 10,
    "min_level": "debug",
    "date_format": "Y-m-d H:i:s",
    "filename_pattern": "{channel}_{date}.log",
    "include_context": true,
    "file_permissions": 755,
    "max_file_size": 0,
    "max_files": 0
}
```

**Опции:**

- `log_dir` – директория для хранения лог-файлов. Если `null`, используется `app/logs/`.
- `flush_limit` – количество записей в буфере перед принудительной записью на диск.
- `min_level` – минимальный уровень логирования (debug, info, notice, warning, error, critical, alert, emergency).
- `date_format` – формат даты в лог-файле.
- `filename_pattern` – шаблон имени файла. Поддерживаются плейсхолдеры `{channel}`, `{date}`, `{level}`.
- `include_context` – включать ли контекст в лог-файл.
- `file_permissions` – права на создаваемые файлы (в восьмеричном формате).
- `max_file_size` – максимальный размер файла в байтах (0 – без ограничений).
- `max_files` – максимальное количество файлов логов (0 – без ограничений).

### Уровни логирования

Поддерживаются 8 уровней логирования в соответствии с PSR-3 (от наименее к наиболее критичным):

1. **debug** – отладочная информация, подробности работы.
2. **info** – информационные сообщения (например, «Пользователь залогинен»).
3. **notice** – нормальные, но значимые события.
4. **warning** – предупреждения, не критические проблемы.
5. **error** – ошибки выполнения, требующие внимания.
6. **critical** – критические условия (например, недоступность компонента).
7. **alert** – тревоги, требующие немедленного действия.
8. **emergency** – аварийная ситуация, система неработоспособна.

Уровень `min_level` определяет, какие сообщения будут записываться. Например, при `min_level = "warning"` сообщения уровня `debug`, `info`, `notice` игнорируются.

### Каналы

Каналы позволяют разделять логи по функциональным областям. По умолчанию доступны каналы:

- `app` – общие логи приложения.
- `database` – логи базы данных (запросы, ошибки).
- `security` – безопасность (авторизация, аутентификация).
- `system` – системные события (запуск, остановка).
- `debug` – отладочные сообщения.
- `error` – ошибки приложения.

Вы можете создавать собственные каналы.

## Использование логгера

### Получение логгера

Логгер доступен через контейнер зависимостей:

```php
$logger = $this->container->get('logger');
```

Или в контроллере через свойство (если подключен трейт):

```php
$this->logger->info('Сообщение');
```

### Базовое логирование

```php
// Разные уровни
$this->logger->debug('Отладочное сообщение');
$this->logger->info('Информационное сообщение');
$this->logger->notice('Заметка');
$this->logger->warning('Предупреждение');
$this->logger->error('Ошибка');
$this->logger->critical('Критическая ошибка');
$this->logger->alert('Тревога');
$this->logger->emergency('Аварийная ситуация');
```

### Логирование с контекстом

Контекст – это массив дополнительных данных, которые прикрепляются к лог-сообщению.

```php
$this->logger->info('Пользователь залогинен', [
    'user_id' => 42,
    'ip' => '192.168.1.1',
    'user_agent' => $_SERVER['HTTP_USER_AGENT'],
]);
```

Контекст также используется для интерполяции плейсхолдеров в сообщении (см. ниже).

### Логирование по каналам

**Создание логгера для конкретного канала:**

```php
$dbLogger = $this->logger->channel('database');
$dbLogger->info('Запрос выполнен', ['query' => 'SELECT * FROM users']);
```

**Логирование с указанием канала в одном вызове:**

```php
$this->logger->logWithChannel('info', 'Запрос выполнен', ['query' => '...'], 'database');
```

**Изменение канала по умолчанию:**

```php
$this->logger->setChannel('security');
$this->logger->warning('Попытка несанкционированного доступа');
```

## Формат логов

### Структура записи

Каждая запись лога содержит следующие поля:

- `time` – время в формате, заданном в конфигурации.
- `timestamp` – метка времени с микросекундами (float).
- `level` – уровень логирования.
- `channel` – канал.
- `message` – текст сообщения.
- `context` – контекст (массив).

**Пример записи в файле:**

```
[2026-03-13 23:45:12] app.INFO: Пользователь залогинен {"user_id":42,"ip":"192.168.1.1"}
```

### Интерполяция контекста

Вы можете использовать плейсхолдеры `{key}` в тексте сообщения, которые будут заменены значениями из контекста:

```php
$this->logger->info('Пользователь {user} залогинен с IP {ip}', [
    'user' => 'john_doe',
    'ip' => '192.168.1.1',
]);
```

Результат в логе: `Пользователь john_doe залогинен с IP 192.168.1.1`

Если значение не скалярное и не имеет метода `__toString()`, плейсхолдер не заменяется.

## Настройка писателей (writers)

### FileLogWriter

По умолчанию используется `FileLogWriter`, который записывает логи в файлы. Настройки писателя определяются в `logger.json`.

**Шаблон имени файла:**

- `{channel}` – заменяется на имя канала.
- `{date}` – заменяется на текущую дату (формат `Y-m-d`).
- `{level}` – заменяется на уровень логирования.

Пример: `filename_pattern = "{channel}_{date}.log"` создаст файл `app_2026-03-13.log` для канала `app`.

**Ротация логов:**

Если `max_file_size > 0`, при достижении размера файл будет переименован (добавляется суффикс `.1`, `.2` и т.д.). Максимальное количество файлов контролируется `max_files`.

### Создание собственного писателя

Вы можете реализовать интерфейс `LogWriterInterface` для записи логов в другое хранилище (база данных, syslog, Slack, etc.).

```php
<?php
namespace App\Logger;

use Architect\Services\Logger\LogWriterInterface;

class DatabaseWriter implements LogWriterInterface
{
    public function write(array $entries): void
    {
        foreach ($entries as $entry) {
            // Вставка в таблицу logs
            DB::table('logs')->insert([
                'level' => $entry['level'],
                'channel' => $entry['channel'],
                'message' => $entry['message'],
                'context' => json_encode($entry['context']),
                'created_at' => $entry['time'],
            ]);
        }
    }
}
```

Зарегистрируйте писатель в контейнере:

```php
$container->set('log_writer', new DatabaseWriter());
```

Или передайте в конструктор логгера:

```php
$logger = new Logger($container, $config, new DatabaseWriter());
```

## Интеграция с Debug Panel

Логи автоматически отображаются в отладочной панели (если она включена). Для этого используется callback-механизм, который избегает циклических зависимостей.

Вы можете отключить интеграцию, не устанавливая callback:

```php
$logger->setDebugCallback(null);
```

В отладочной панели логи отображаются в секции **Logs** с цветовой индикацией по уровням:

- **debug** – серый
- **info** – синий
- **warning** – жёлтый
- **error** – красный
- **critical/alert/emergency** – красный жирный

## Лучшие практики

1. **Используйте соответствующие уровни** – не логируйте отладочную информацию как error, и наоборот.

2. **Добавляйте контекст** – вместо `"Файл не найден"` лучше `"Файл {file} не найден"` с контекстом `['file' => '/path/to/file']`.

3. **Разделяйте логи по каналам** – это упрощает анализ и мониторинг.

4. **Настройте ротацию логов** – чтобы логи не занимали всё дисковое пространство.

5. **В production повысьте min_level** – установите `min_level = "warning"` или `"error"`, чтобы избежать шума.

6. **Используйте буферизацию** – не меняйте `flush_limit` без необходимости, слишком маленькое значение снизит производительность.

7. **Мониторьте логи** – настройте алерты на критические и emergency-сообщения.

## Частые вопросы

**Вопрос: Где хранятся файлы логов по умолчанию?**

Ответ: В директории `app/logs/`. Имена файлов формируются по шаблону `{channel}_{date}.log`.

**Вопрос: Как логировать исключения (exceptions)?**

Ответ: Передавайте исключение в контексте:

```php
try {
    // код
} catch (Exception $e) {
    $this->logger->error('Ошибка при выполнении операции', [
        'exception' => $e->getMessage(),
        'trace' => $e->getTraceAsString(),
    ]);
}
```

**Вопрос: Можно ли использовать несколько логгеров одновременно?**

Ответ: Да, создавайте логгеры для разных каналов через `$logger->channel('name')`. Каждый канал может иметь свои настройки (если настроено).

**Вопрос: Как отключить логирование в файл и писать только в отладочную панель?**

Ответ: Создайте custom writer, который ничего не делает, и установите его как writer по умолчанию.

**Вопрос: Как изменить формат вывода логов в файле?**

Ответ: Реализуйте собственный writer, который форматирует записи по-своему, или расширьте `FileLogWriter`.

**Вопрос: Логи не записываются. В чём может быть проблема?**

Ответ: Проверьте:
- Права на запись в директорию логов.
- Уровень `min_level` (возможно, ваше сообщение имеет более низкий уровень).
- Наличие вызова `flush()` (логи буферизуются и записываются при достижении лимита или в конце запроса).
