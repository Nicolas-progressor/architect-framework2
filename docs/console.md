
# Консольные команды Architect RED 2

## Введение

Консольные команды — это мощный инструмент для автоматизации рутинных задач разработки в Architect RED 2. С их помощью вы можете создавать компоненты приложения (приложения, модули, контроллеры, модели, представления, маршруты), управлять миграциями базы данных, очищать кэш, просматривать маршруты и многое другое — всё без необходимости вручную создавать файлы и папки.

Эта документация предназначена как для начинающих, так и для опытных разработчиков. Мы постарались сделать её максимально подробной и понятной, чтобы вы могли быстро освоить консольный интерфейс и использовать его в повседневной работе.

## Установка и настройка

Консольный интерфейс входит в состав фреймворка и устанавливается автоматически при установке Architect RED 2. Для работы консоли требуется PHP 8.1 или выше, а также расширения, которые обычно включены в стандартную поставку PHP (например, `mbstring`, `json`, `pdo`).

### Проверка доступности

После установки фреймворка откройте терминал в корневой папке проекта и выполните:

```bash
php bin/arc list
```

Если вы видите список команд, значит консоль работает корректно. Если возникает ошибка, убедитесь, что:

- Вы находитесь в корневой папке проекта (там, где находятся `composer.json`, `app/`, `architect/`).
- PHP установлен и добавлен в переменную окружения PATH.
- Все зависимости установлены (`composer install`).

### Альтернативные способы запуска

- **Через Composer**: `composer arc list` (если в `composer.json` настроены скрипты).
- **Прямой вызов**: `php arc` (если файл `arc` находится в корне проекта и имеет права на выполнение).

## Структура консольных команд

Все команды организованы в группы по функциональности:

| Группа | Описание | Примеры команд |
|--------|----------|----------------|
| **make** | Создание компонентов приложения | `make:app`, `make:module`, `make:controller` |
| **db** | Работа с базой данных | `db:migrate`, `db:rollback`, `db:seed` |
| **cache** | Управление кэшем | `cache:clear`, `config:cache` |
| **route** | Работа с маршрутами | `route:list` |
| **arc** | Информация о проекте | `arc:info` |
| **optimize** | Оптимизация | `optimize:autoload` |
| **test** | Тестирование | `test:run` |

Каждая команда поддерживает опцию `--help`, которая выводит подробную справку по использованию.

## Основные команды с примерами

### 1. Создание приложения

Приложение — это логически обособленная часть проекта со своей структурой модулей, маршрутов и конфигураций. Architect RED 2 поддерживает несколько приложений в одном проекте (например, `home` для публичной части, `admin` для панели управления, `api` для REST API).

**Команда:**
```bash
php arc make:app <name> [опции]
```

**Опции:**
- `--modules` — список модулей, которые нужно создать внутри приложения (через запятую).
- `--force` — перезаписать существующее приложение, если оно уже есть.

**Примеры:**

```bash
# Создать приложение "admin" без дополнительных модулей
php arc make:app admin

# Создать приложение "shop" с модулями "products", "cart", "orders"
php arc make:app shop --modules=products,cart,orders

# Принудительно пересоздать приложение (если оно уже существует)
php arc make:app api --force
```

**Что создаётся:**
```
app/apps/{name}/
├── modules/          # Папка для модулей (если указаны — создаются подпапки)
├── routes/           # Папка для маршрутов приложения
├── template/         # Папка для шаблонов приложения
└── config/           # Папка для конфигурации приложения
```

### 2. Создание модуля

Модуль — это группа связанных функциональностей (например, управление пользователями, каталог товаров, блог). Модуль может быть привязан к конкретному приложению или быть глобальным (доступным для всех приложений).

**Команда:**
```bash
php arc make:module <name> [опции]
```

**Опции:**
- `--app` — имя приложения, в котором будет создан модуль (по умолчанию `home`).
- `--global` — создать глобальный модуль (будет размещён в `app/modules/`).
- `--controller` — сразу создать контроллер внутри модуля.
- `--model` — сразу создать модель внутри модуля.
- `--view` — сразу создать представление внутри модуля.

**Примеры:**

```bash
# Создать модуль "users" в приложении "home"
php arc make:module users --app=home

# Создать глобальный модуль "api" (доступен всем приложениям)
php arc make:module api --global

# Создать модуль "products" с контроллером и моделью
php arc make:module products --app=shop --controller --model
```

**Что создаётся:**
```
app/apps/{app}/modules/{name}/
├── controller/       # Папка для контроллеров
├── model/            # Папка для моделей
├── view/             # Папка для представлений
└── lang/             # Папка для языковых файлов (опционально)
```

### 3. Создание контроллера

Контроллер обрабатывает HTTP-запросы, взаимодействует с моделью и возвращает представление. Команда `make:controller` создаёт класс контроллера с базовой структурой.

**Команда:**
```bash
php arc make:controller <name> [опции]
```

**Опции:**
- `--module` — имя модуля, в котором будет создан контроллер (обязательно, если модуль не глобальный).
- `--app` — имя приложения (по умолчанию `home`).
- `--resource` — создать ресурсный контроллер с CRUD-методами (index, create, store, show, edit, update, destroy).
- `--api` — создать API-контроллер (без методов create и edit, возвращает JSON).
- `--force` — перезаписать существующий контроллер.

**Примеры:**

```bash
# Создать простой контроллер "UserController" в модуле "users" приложения "home"
php arc make:controller UserController --module=users --app=home

# Создать ресурсный контроллер для управления товарами
php arc make:controller ProductController --module=products --app=shop --resource

# Создать API-контроллер для работы с заказами
php arc make:controller OrderController --module=orders --app=shop --api
```

**Структура создаваемого файла:**

```php
<?php

declare(strict_types=1);

namespace app\home\modules\users\controller;

use Architect\Services\Mvc\Controller;

class UserController extends Controller
{
    public function index_app_data(): void
    {
        // Подготовка данных для представления
    }

    public function index_app_output(): void
    {
        // Рендеринг представления
        $this->display('index');
    }
}
```

### 4. Создание модели

Модель представляет бизнес-сущность и отвечает за работу с данными (обычно с таблицей базы данных). Команда `make:model` создаёт класс модели, расширяющий `ModelBase`.

**Команда:**
```bash
php arc make:model <name> [опции]
```

**Опции:**
- `--module` — имя модуля, в котором будет создана модель.
- `--app` — имя приложения (по умолчанию `home`).
- `--table` — имя таблицы базы данных (по умолчанию вычисляется из имени модели).
- `--force` — перезаписать существующую модель.

**Примеры:**

```bash
# Создать модель "User" в модуле "users"
php arc make:model User --module=users --app=home

# Создать модель "Product" с указанием таблицы "products"
php arc make:model Product --module=products --app=shop --table=products
```

**Структура создаваемого файла:**

```php
<?php

declare(strict_types=1);

namespace app\home\modules\users\model;

use Architect\Services\Mvc\ModelBase;

class User extends ModelBase
{
    // Здесь можно добавить методы для работы с данными
    public function getAll(): array
    {
        // Пример реализации
        return [];
    }
}
```

### 5. Создание представления

Представление — это файл шаблона, который отвечает за отображение данных. Команда `make:view` создаёт пустой файл представления в нужной папке.

**Команда:**
```bash
php arc make:view <name> [опции]
```

**Опции:**
- `--module` — имя модуля.
- `--app` — имя приложения (по умолчанию `home`).
- `--type` — тип шаблона (`php` или `blu`). По умолчанию `php`.
- `--force` — перезаписать существующее представление.

**Примеры:**

```bash
# Создать PHP-представление "profile" в модуле "users"
php arc make:view profile --module=users --app=home --type=php

# Создать Blueprint-представление "index" для модуля "products"
php arc make:view index --module=products --app=shop --type=blu
```

**Что создаётся:**
- Для типа `php`: `app/apps/{app}/modules/{module}/view/{name}.php`
- Для типа `blu`: `app/apps/{app}/modules/{module}/view/{name}.blu`

### 6. Создание маршрута

Маршрут связывает URL с контроллером и действием. Команда `make:route` создаёт JSON-файл маршрута в папке приложения или глобально.

**Команда:**
```bash
php arc make:route <name> [опции]
```

**Опции:**
- `--app` — имя приложения (по умолчанию `home`).
- `--module` — имя модуля (обязательно).
- `--controller` — имя контроллера (обязательно).
- `--action` — имя действия (обязательно).
- `--global` — создать глобальный маршрут (в `app/routes/`).
- `--method` — HTTP-метод (GET, POST, PUT, DELETE, ANY). По умолчанию `ANY`.
- `--force` — перезаписать существующий маршрут.

**Примеры:**

```bash
# Создать маршрут "users" для приложения "home"
php arc make:route users --app=home --module=users --controller=users --action=index

# Создать глобальный маршрут для API
php arc make:route api/v1/products --global --module=products --controller=ProductController --action=index --method=GET
```

**Структура создаваемого файла:**

```json
{
    "default": "index",
    "routes": {
        "users": {
            "module": "users",
            "controller": "users",
            "action": "index"
        }
    }
}
```

### 7. Работа с миграциями базы данных

Миграции позволяют управлять схемой базы данных в контролируемом порядке. Architect RED 2 использует собственную систему миграций, интегрированную с Axiom ORM.

**Создание миграции:**
```bash
php arc make:migration <name> [опции]
```

Опции:
- `--create` — миграция для создания новой таблицы.
- `--modify` — миграция для изменения существующей таблицы.
- `--table` — имя таблицы (если не указано, вычисляется из имени миграции).

**Примеры:**

```bash
# Создать миграцию для создания таблицы "users"
php arc make:migration create_users_table --create --table=users

# Создать миграцию для добавления столбца "email" в таблицу "users"
php arc make:migration add_email_to_users --modify --table=users
```

**Выполнение миграций:**
```bash
# Применить все pending-миграции
php arc db:migrate

# Применить миграции с принудительным подтверждением
php arc db:migrate --force

# Откатить последнюю применённую миграцию
php arc db:rollback

# Откатить все миграции
php arc db:rollback --all
```

**Заполнение базы данных (сидеры):**
```bash
# Запустить сидеры
php arc db:seed

# Запустить конкретный сидер
php arc db:seed --class=UserSeeder
```

### 8. Управление кэшем

Фреймворк кэширует конфигурацию, маршруты и скомпилированные шаблоны Blueprint для повышения производительности. Команды `cache:clear` и `config:cache` позволяют управлять этим кэшем.

**Очистка кэша:**
```bash
# Очистить весь кэш
php arc cache:clear --all

# Очистить только кэш конфигурации
php arc cache:clear --config

# Очистить только кэш маршрутов
php arc cache:clear --routes

# Очистить только кэш шаблонов Blueprint
php arc cache:clear --blueprint
```

**Кэширование конфигурации:**
```bash
# Создать кэш-файл конфигурации
php arc config:cache
```

После кэширования конфигурации фреймворк будет загружать настройки из скомпилированного файла, что значительно ускоряет запуск приложения. Рекомендуется использовать эту команду в production-окружении.

### 9. Просмотр маршрутов

Команда `route:list` выводит таблицу всех зарегистрированных маршрутов с информацией о модуле, контроллере, действии и HTTP-методах.

```bash
# Вывести все маршруты
php arc route:list

# Вывести маршруты только для приложения "home"
php arc route:list --app=home

# Подробный вывод с дополнительной информацией
php arc route:list --verbose
```

### 10. Информация о проекте

Команда `arc:info` показывает сводную информацию о проекте: версию фреймворка, окружение, список приложений, активные сервисы и т.д.

```bash
php arc arc:info
```

## Создание собственных команд

Architect RED 2 позволяет легко расширять консоль, добавляя свои команды. Это полезно для автоматизации специфичных для проекта задач (например, генерация отчётов, отправка уведомлений, синхронизация с внешними API).

### Шаг 1: Создание класса команды

Создайте файл в директории `app/Console/Commands/` (если её нет — создайте). Класс должен реализовывать интерфейс `Architect\Console\CommandInterface` или расширять `Architect\Console\BaseCommand` (рекомендуется).

**Пример команды `app/Console/Commands/HelloCommand.php`:**

```php
<?php

declare(strict_types=1);

namespace app\Console\Commands;

use Architect\Console\BaseCommand;
use Architect\Console\CommandInterface;

class HelloCommand extends BaseCommand implements CommandInterface
{
    // Имя команды (как она будет вызываться)
    protected string $name = 'hello';

    // Описание команды (отображается в списке)
    protected string $description = 'Выводит приветственное сообщение';

    // Псевдонимы (альтернативные имена)
    protected array $aliases = ['hi', 'greet'];

    /**
     * Определение аргументов команды.
     * Формат: [имя, описание, обязательный?]
     */
    public function getArguments(): array
    {
        return [
            ['name', 'Имя пользователя', false],
        ];
    }

    /**
     * Определение опций команды.
     * Формат: [имя, описание]
     */
    public function getOptions(): array
    {
        return [
            ['--formal', 'Формальное приветствие'],
            ['--repeat', 'Количество повторений', 'int
            ],
        ];
    }

    /**
     * Выполнение команды.
     */
    public function execute(array $arguments, array $options): int
    {
        $name = $arguments['name'] ?? 'мир';
        $formal = $options['formal'] ?? false;
        $repeat = (int) ($options['repeat'] ?? 1);

        $greeting = $formal ? "Здравствуйте, $name!" : "Привет, $name!";

        for ($i = 0; $i < $repeat; $i++) {
            $this->success($greeting);
        }

        return 0; // Код успешного завершения
    }
}
```

### Шаг 2: Регистрация команды

Команды автоматически обнаруживаются, если они находятся в директории `app/Console/Commands/` и соответствуют PSR-4 автозагрузке. Убедитесь, что ваш класс загружается (проверьте `composer.json` и пространство имён).

Если вы хотите разместить команду в другом месте, зарегистрируйте её вручную в файле `bin/arc`:

```php
use Architect\Console\ConsoleKernel;
use app\Console\Commands\HelloCommand;

$console = new ConsoleKernel();
$console->registerCommand(new HelloCommand());
$console->run();
```

### Шаг 3: Использование команды

После создания команды она появится в списке:

```bash
php arc list
```

Запустите её:

```bash
php arc hello Иван --formal --repeat=3
```

Вывод:
```
✔ Привет, Иван!
✔ Привет, Иван!
✔ Привет, Иван!
```

## Лучшие практики

1. **Используйте опцию `--help`** — всегда добавляйте подробное описание команды и её параметров, чтобы другие разработчики могли быстро разобраться.

2. **Следуйте конвенциям именования** — имена команд должны быть в формате `группа:действие` (например, `user:activate`, `report:generate`).

3. **Возвращайте корректные коды завершения** — 0 при успехе, положительные числа при ошибках (1 — общая ошибка, 2 — неверные аргументы и т.д.).

4. **Используйте встроенные методы вывода** — `$this->success()`, `$this->error()`, `$this->warning()`, `$this->info()` для единообразного форматирования.

5. **Избегайте side‑effects в конструкторе** — вся логика должна быть в методе `execute()`.

6. **Пишите тесты** — консольные команды легко тестировать, создавая экземпляр команды и передавая аргументы/опции.

7. **Документируйте сложные команды** — если команда выполняет нетривиальные действия, добавьте комментарии в код и, возможно, отдельный раздел в документации.

## Часто задаваемые вопросы

### Вопрос: Команда не появляется в списке. Что делать?

**Ответ:** Проверьте:
- Класс команды находится в директории `app/Console/Commands/`.
- Пространство имён соответствует PSR-4.
- Класс реализует `CommandInterface` или расширяет `BaseCommand`.
- Вы выполнили `composer dump-autoload`.

### Вопрос: Как передать аргументы с пробелами?

**Ответ:** Заключите аргумент в кавычки:
```bash
php arc hello "Иван Петров"
```

### Вопрос: Можно ли вызывать команды из кода приложения?

**Ответ:** Да, используйте `Architect\Console\Console::runCommand()`:
```php
use Architect\Console\Console;

$exitCode = Console::runCommand('cache:clear', [], ['--all' => true]);
```

### Вопрос: Как отключить цветной вывод?

**Ответ:** Установите переменную окружения `NO_COLOR=1` или используйте опцию `--no-ansi`:
```bash
php arc arc:info --no-ansi
```

### Вопрос: Где хранятся логи консольных команд?

**Ответ:** По умолчанию консольные команды не логируются. Вы можете добавить логирование вручную внутри команды, используя сервис `logger`:
```php
$logger = $this->container->get('logger');
$logger->info('Команда выполнена');
```
