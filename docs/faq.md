# Часто задаваемые вопросы (FAQ)

В этом разделе собраны ответы на распространённые вопросы по использованию Architect RED 2.

## Общие вопросы

### Что такое Architect RED 2?

Architect RED 2 – это PHP-фреймворк для построения веб-приложений, основанный на паттерне MVC и принципах модульности. Он включает в себя шаблонизатор Blueprint, ORM Axiom, систему аутентификации, отладочную панель и другие компоненты.

### Какие версии PHP поддерживаются?

Требуется PHP 8.1 или выше. Рекомендуется использовать последнюю стабильную версию PHP 8.2 или 8.3.

### Какой веб-сервер рекомендуется?

Architect работает с любым веб-сервером (Apache, Nginx, Caddy). Для production рекомендуется Nginx с PHP-FPM.

### Architect – это микрофреймворк или полноценный фреймворк?

Architect – полноценный фреймворк с богатым набором компонентов, но при этом он остаётся модульным и позволяет использовать только нужные части.

## Установка и настройка

### Как установить Architect?

Самый простой способ – использовать Composer:

```bash
composer create-project architect/framework myapp
```

Или клонировать репозиторий и установить зависимости:

```bash
git clone https://github.com/architect-framework/architect-red2.git
cd architect-red2
composer install
```

### Где находится конфигурация?

Основная конфигурация хранится в папке `app/config/`. Файлы имеют расширение `.json`. Также есть конфигурация окружений в `app/config/environment/`.

### Как изменить окружение?

Установите переменную окружения `APP_ENV` (например, `production`, `development`). По умолчанию используется `development`.

### Как подключить базу данных?

Создайте файл `app/config/database.json` с настройками соединения. Подробнее см. в [документации по базе данных](database.md).

## Разработка

### Как создать контроллер?

Создайте файл в папке модуля, например `app/modules/example/controller.php`:

```php
<?php

namespace App\Modules\Example;

use Architect\Services\Mvc\Controller;

class ExampleController extends Controller
{
    public function index()
    {
        return $this->view('index');
    }
}
```

### Как добавить маршрут?

Добавьте запись в JSON-файл маршрутов (например, `app/routes/home.json`):

```json
{
    "route": "/example",
    "controller": "Example\\ExampleController",
    "methods": ["GET"]
}
```

### Как использовать шаблонизатор Blueprint?

Убедитесь, что Blueprint установлен (`composer require architect/blueprint`). Затем в контроллере:

```php
return $this->blueprint('template_name', ['data' => $value]);
```

Шаблоны должны находиться в `app/template/` с расширением `.blu`.

### Как работать с базой данных?

Используйте Axiom ORM. Пример:

```php
use Axiom\Orm\Orm;

$users = Orm::table('users')->where('active', 1)->get();
```

Или используйте трейт `ModelOrmTrait` в моделях.

### Как реализовать аутентификацию?

Установите модуль аутентификации:

```bash
composer require architect/auth-system
```

Затем настройте `app/config/auth.json` и используйте middleware `auth` в маршрутах.

## Ошибки и отладка

### Включена отладочная панель, но она не показывается

Убедитесь, что в конфигурации `app/config/debug.json` параметр `enabled` установлен в `true`. Также проверьте, что вы не в production-окружении (debug панель отключается автоматически).

### Получаю ошибку "Class not found"

Проверьте пространство имён и автозагрузку Composer. Выполните:

```bash
composer dump-autoload
```

Убедитесь, что класс находится в правильной директории и namespace соответствует PSR-4.

### Ошибка 404 на всех страницах

Проверьте конфигурацию веб-сервера (правила перенаправления). Убедитесь, что запросы перенаправляются на `index.php`. Также проверьте маршруты – возможно, нет подходящего.

### Как посмотреть логи?

Логи хранятся в `app/logs/`. Имена файлов соответствуют дате и каналу (например, `app_2026-03-13.log`). Вы также можете использовать Debug Panel для просмотра логов в реальном времени.

## Производительность

### Как включить кэширование шаблонов?

В конфигурации Blueprint (`app/config/template.json`) установите `"cache": true` и укажите `"cache_path"`.

### Как оптимизировать загрузку CSS/JS?

Используйте хелпер `Assets` для конкатенации и минификации. Также можно использовать внешние сборщики (Vite, Webpack).

### Как уменьшить время ответа сервера?

- Включите OPCache.
- Используйте кэширование запросов к БД.
- Минимизируйте количество запросов к базе.
- Используйте CDN для статических файлов.

## Развёртывание

### Как подготовить приложение к production?

1. Установите `APP_ENV=production`.
2. Отключите debug (`"debug": false`).
3. Включите кэширование шаблонов.
4. Настройте правильные права на файлы.
5. Используйте HTTPS.

### Как обновить приложение без простоя?

Используйте стратегию blue-green deployment или хотя бы выполняйте миграции до переключения трафика.

### Как настроить cron-задачи?

Создайте PHP-скрипт, который использует компоненты Architect, и добавьте его в crontab:

```cron
* * * * * cd /path/to/project && php bin/arc schedule:run
```

## Расширение

### Как создать собственный модуль?

Создайте папку в `app/modules/yourmodule/` с файлами `controller.php`, `model.php`, `view/`. Затем добавьте маршруты.

### Как добавить собственный сервис в контейнер?

Создайте сервис-провайдер и зарегистрируйте его в `bootstrap.php` или через конфигурацию.

### Можно ли использовать сторонние библиотеки?

Да, Architect полностью совместим с любыми библиотеками Composer. Просто установите их и используйте как обычно.

## Миграции

### Как создать миграцию?

```bash
php vendor/bin/axiom make:migration create_table_name
```

### Как откатить миграцию?

```bash
php vendor/bin/axiom rollback
```

### Где хранятся миграции?

В папке `migrations/` в корне проекта.

## Безопасность

### Как защититься от SQL-инъекций?

Используйте Axiom ORM с подготовленными выражениями. Никогда не вставляйте пользовательские данные напрямую в SQL-строку.

### Как включить CSRF-защиту?

Добавьте middleware `csrf` к POST-маршрутам и используйте `{{ csrf_token() }}` в формах.

### Как хешировать пароли?

Используйте `password_hash()` и `password_verify()`.
