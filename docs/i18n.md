# Интернационализация (i18n)

Architect Framework предоставляет встроенную систему интернационализации (i18n) для поддержки многоязычных приложений. Система позволяет управлять переводами, определять языковые настройки через URL, cookies и конфигурацию, а также автоматически перенаправлять пользователей на предпочтительный язык.

## Введение

Система i18n в Architect Framework построена вокруг сервиса `Language`, который:

- Определяет текущий язык пользователя на основе URL, cookie или конфигурации.
- Загружает файлы переводов в формате JSON.
- Предоставляет методы для получения переводов по ключам.
- Поддерживает автоматическое перенаправление на предпочтительный язык.

Языковые коды соответствуют стандарту ISO 639-1 (например, `ru`, `en`, `de`). Поддерживаются также региональные варианты (например, `en-US`, `en-GB`).

## Конфигурация

### Файл lang.json

Основные настройки интернационализации хранятся в `app/config/lang.json`:

```json
{
    "defaults": {
        "system_default": "en",
        "system_langs": {
            "0": "ru",
            "1": "en",
            "2": "be",
            "3": "ua",
            "4": "ky",
            "5": "ab",
            "6": "mo",
            "7": "et",
            "8": "lv",
            "9": "eu",
            "10": "us"
        }
    },
    "routing": {
        "enable_lang_routing": true
    },
    "redirect": {
        "enabled": true,
        "rules": {
            "ru": {
                "0": "be",
                "1": "ua",
                "2": "ky",
                "3": "ab",
                "4": "mo",
                "5": "et",
                "6": "lv"
            },
            "en": {
                "0": "eu",
                "1": "us"
            }
        }
    },
    "cookies": {
        "setup_cookie": true,
        "routing_cookie": true,
        "cookie_lifetime": 0
    },
    "all_langs": {
        "en": "English",
        "ru": "Русский"
    }
}
```

### Настройки по умолчанию

- `system_default` – язык по умолчанию, если не удалось определить язык пользователя.
- `system_langs` – список поддерживаемых языков системы.

### Маршрутизация по языкам

- `enable_lang_routing` – включить/выключить маршрутизацию с языковыми префиксами (например, `/en/about`).
- Если маршрутизация включена, URL будут автоматически обрабатываться с учётом языка.

### Перенаправления

- `redirect.enabled` – включить автоматическое перенаправление пользователей на предпочтительный язык.
- `redirect.rules` – правила перенаправления. Например, пользователи с языком `be` (белорусский) будут перенаправлены на `ru`, если нет перевода на белорусский.

### Cookies

- `setup_cookie` – устанавливать cookie с выбранным языком.
- `routing_cookie` – использовать cookie для определения языка при маршрутизации.
- `cookie_lifetime` – время жизни cookie (0 – до закрытия браузера).

## Использование в приложении

### Сервис Language

Сервис Language доступен через контейнер зависимостей:

```php
$lang = $this->container->get('language');
```

Или в контроллере через свойство (если подключен трейт):

```php
$currentLang = $this->language->getLanguage();
```

### Получение текущего языка

Текущий язык определяется в следующем порядке приоритета:

1. Параметр `lang` в URL (`?lang=en`).
2. Cookie `lang`.
3. Язык по умолчанию из конфигурации.

```php
$lang = $this->language->getLanguage(); // например, 'ru'
```

Также доступна константа `ARC_LANG`, определённая после инициализации сервиса.

### Установка языка

Вы можете программно установить язык для текущего запроса:

```php
$this->language->setLanguage('en');
```

Установка языка также обновляет cookie (если включено в конфигурации).

## Файлы переводов

### Структура файлов

Переводы хранятся в JSON-файлах внутри модулей. Путь к файлу:

```
app/modules/{module}/lang/{section}/{section}.json
```

Пример для модуля `auth` и секции `login`:

```
app/modules/auth/lang/login/login.json
```

### Формат файла перевода

Файл содержит переводы для каждого языка:

```json
{
    "ru": {
        "welcome": "Добро пожаловать",
        "login": "Войти",
        "logout": "Выйти"
    },
    "en": {
        "welcome": "Welcome",
        "login": "Sign in",
        "logout": "Sign out"
    },
    "de": {
        "welcome": "Willkommen",
        "login": "Anmelden",
        "logout": "Abmelden"
    }
}
```

### Загрузка переводов

Загрузка переводов выполняется автоматически при первом обращении к ключу или вручную:

```php
// Загрузить все переводы для секции 'login' модуля 'auth'
$this->language->file('login', 'auth');
```

После загрузки переводы кэшируются в памяти на время выполнения запроса.

### Получение переводов

**Получить перевод по ключу:**

```php
$translation = $this->language->get('login.welcome');
// Ищет в загруженных переводах ключ 'welcome' в секции 'login'
```

Если перевод не найден, возвращается значение по умолчанию (можно указать третьим параметром):

```php
$translation = $this->language->get('login.welcome', null, 'Welcome');
```

**Получить перевод с указанием модуля (автоматическая загрузка):**

```php
$translation = $this->language->get('welcome', 'auth');
// Загрузит файл app/modules/auth/lang/welcome/welcome.json
// и вернёт перевод для текущего языка
```

**Альтернативный метод `trans`:**

```php
$translation = $this->language->trans('login', 'welcome');
```

**Получить все переводы для секции:**

```php
$allLoginTranslations = $this->language->getAll('login');
```

**Проверить наличие перевода:**

```php
if ($this->language->has('login', 'welcome')) {
    // перевод существует
}
```

## Использование в шаблонах

### Хелперы Blueprint

В шаблонизаторе Blueprint доступны функции для работы с переводами:

```blu
{{ trans('login.welcome') }}
{{ trans('login.welcome', 'auth') }}
{{ trans('login.welcome', 'auth', 'Welcome') }}
```

Также можно использовать фильтр `|trans`:

```blu
{{ 'login.welcome'|trans }}
```

### Динамическое переключение языка

Создайте форму или ссылки для переключения языка:

```html
<ul class="lang-switcher">
    <li><a href="?lang=ru">Русский</a></li>
    <li><a href="?lang=en">English</a></li>
    <li><a href="?lang=de">Deutsch</a></li>
</ul>
```

При переходе по ссылке язык будет изменён и сохранён в cookie.

## Маршрутизация с языковыми префиксами

Если в конфигурации включена опция `enable_lang_routing`, маршруты могут включать языковой префикс:

```
/en/about
/ru/about
/de/about
```

Маршруты без префикса используют язык по умолчанию.

**Пример конфигурации маршрута с поддержкой языка:**

```json
{
    "route": "/about",
    "controller": "AboutController",
    "action": "index",
    "lang": true
}
```

**Определение языка в контроллере:**

```php
public function index()
{
    $lang = $this->language->getLanguage(); // 'en', 'ru' и т.д.
    // Загружаем переводы для текущего языка
    $title = $this->language->get('about.title', 'about');
    
    return $this->view('about/index', [
        'lang' => $lang,
        'title' => $title,
    ]);
}
```

## Лучшие практики

1. **Используйте ключи перевода вместо жёстко закодированных строк** – это упростит поддержку многоязычности.

2. **Организуйте переводы по модулям и секциям** – группируйте связанные переводы (например, `auth.login`, `auth.register`).

3. **Предоставьте fallback-переводы** – всегда включайте язык по умолчанию (например, `en`) в файлы переводов.

4. **Кэшируйте переводы в production** – используйте кэширование, чтобы избежать частого чтения файлов.

5. **Используйте автоматическое перенаправление** – настройте правила перенаправления для похожих языков (например, `be` → `ru`).

6. **Тестируйте интерфейс на разных языках** – убедитесь, что все элементы интерфейса корректно отображаются при смене языка.

## Частые вопросы

**Вопрос: Как добавить новый язык в систему?**

Ответ: Добавьте код языка в `system_langs` в `lang.json` и создайте соответствующие файлы переводов в каждом модуле.

**Вопрос: Что делать, если перевод для ключа отсутствует?**

Ответ: Система вернёт значение по умолчанию (если указано) или оригинальный ключ. Рекомендуется всегда указывать fallback-перевод на языке по умолчанию.

**Вопрос: Как отключить маршрутизацию по языкам?**

Ответ: Установите `"enable_lang_routing": false` в конфигурации.

**Вопрос: Как использовать региональные варианты языков (например, en-US)?**

Ответ: Используйте код с дефисом. Файлы переводов должны называться соответственно (например, `en-US`). Система будет искать сначала точное совпадение, затем базовый язык (`en`).

**Вопрос: Можно ли хранить переводы в базе данных вместо файлов?**

Ответ: Да, можно создать собственный сервис, реализующий `LanguageInterface`, и зарегистрировать его в контейнере вместо стандартного.
