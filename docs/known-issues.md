# Известные проблемы и решения

В этом разделе перечислены известные проблемы Architect RED 2, с которыми могут столкнуться разработчики, а также способы их решения или обходные пути.

## Проблемы с установкой

### Ошибка "Class 'Architect\Core\Container' not found" при запуске

**Причина:** Автозагрузка Composer не сработала, либо зависимости не установлены.

**Решение:**
1. Убедитесь, что выполнили `composer install`.
2. Проверьте, что файл `vendor/autoload.php` существует и подключается в `bootstrap.php`.
3. Если используете собственный веб-сервер, перезапустите его.

### Ошибка "Unable to create cache directory"

**Причина:** Нет прав на запись в директорию `cache/` или `app/logs/`.

**Решение:** Установите правильные права:

```bash
chmod 775 cache
chmod 775 app/logs
```

Или измените владельца:

```bash
chown www-data:www-data cache app/logs
```

## Проблемы с маршрутизацией

### Все маршруты возвращают 404

**Причина:**
- Неправильная конфигурация веб-сервера (запросы не перенаправляются на `index.php`).
- Отсутствует файл `.htaccess` (для Apache) или соответствующая конфигурация Nginx.
- Маршруты не загружены из-за ошибки в JSON-файле.

**Решение:**
1. Проверьте, что `index.php` получает управление. Добавьте `phpinfo()` в начало `index.php` и откройте страницу.
2. Для Apache убедитесь, что включён `mod_rewrite` и файл `.htaccess` присутствует.
3. Для Nginx используйте конфигурацию:

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

4. Проверьте синтаксис JSON-файлов маршрутов с помощью валидатора.

### Параметры маршрута не передаются в контроллер

**Причина:** Параметры определяются в шаблоне маршрута (например, `/user/{id}`), но контроллер не получает их.

**Решение:** Убедитесь, что в методе контроллера вы принимаете параметр с тем же именем:

```php
public function show(int $id)
{
    // $id будет передан
}
```

Также проверьте, что маршрут определён с параметром:

```json
{
    "route": "/user/{id}",
    "controller": "UserController",
    "methods": ["GET"]
}
```

## Проблемы с базой данных

### Ошибка "SQLSTATE[HY000] [2002] Connection refused"

**Причина:** Неправильные настройки подключения к БД или сервер БД не запущен.

**Решение:**
1. Проверьте хост, порт, имя пользователя и пароль в `app/config/database.json`.
2. Убедитесь, что СУБД запущена и доступна.
3. Для Docker-окружения проверьте имена сервисов.

### Миграции не применяются

**Причина:** Возможно, таблица `migrations` отсутствует или повреждена.

**Решение:** Создайте таблицу вручную:

```sql
CREATE TABLE migrations (
    id INT AUTO_INCREMENT PRIMARY KEY,
    migration VARCHAR(255) NOT NULL,
    batch INT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Или удалите все миграции и запустите заново:

```bash
php vendor/bin/axiom migrate:reset
php vendor/bin/axiom migrate
```

## Проблемы с шаблонизатором Blueprint

### Шаблон не рендерится, выводится пустая страница

**Причина:**
- Шаблон не найден по указанному пути.
- Ошибка синтаксиса в шаблоне (но в production ошибки скрыты).
- Кэш устарел.

**Решение:**
1. Проверьте, что шаблон существует в `app/template/` с правильным расширением.
2. Включите отображение ошибок, установив `"debug": true` в конфигурации.
3. Очистите кэш шаблонов:

```bash
php bin/arc cache:clear
```

### Фильтры или функции Blueprint не работают

**Причина:** Возможно, фильтр/функция не зарегистрирован или имя указано неверно.

**Решение:** Проверьте документацию Blueprint на наличие нужного фильтра. Если вы добавляли собственные, убедитесь, что регистрация прошла успешно.

## Проблемы с аутентификацией

### Пользователь не аутентифицируется после входа

**Причина:** Сессии не работают (неправильные настройки, отсутствие прав на папку сессий).

**Решение:**
1. Проверьте, что в `php.ini` указан корректный `session.save_path`.
2. Убедитесь, что папка сессий доступна для записи веб-сервером.
3. В production установите `session.cookie_secure = 1` и `session.cookie_httponly = 1`.

### Middleware auth не перенаправляет на страницу входа

**Причина:** Возможно, маршрут входа не определён или middleware настроен неправильно.

**Решение:** Убедитесь, что в конфигурации аутентификации указан правильный `login_route`:

```json
{
    "login_route": "/login",
    "redirect_after_login": "/dashboard"
}
```

## Проблемы с отладочной панелью

### Debug Panel не отображается, хотя debug включён

**Причина:** Панель может быть отключена для данного маршрута или IP-адреса.

**Решение:** Проверьте конфигурацию `app/config/debug.json`:

```json
{
    "enabled": true,
    "allowed_ips": ["127.0.0.1", "::1"],
    "skip_routes": ["/api/*"]
}
```

Убедитесь, что ваш IP в списке `allowed_ips`.

### Панель перекрывает содержимое страницы

**Причина:** Стили конфликтуют со стилями приложения.

**Решение:** Вы можете изменить позиционирование панели через CSS или отключить её для конкретной страницы, добавив маршрут в `skip_routes`.

## Проблемы с производительностью

### Высокая загрузка CPU при использовании кэша файлов

**Причина:** Кэш файлов может быть медленным при большом количестве записей.

**Решение:** Переключитесь на Redis или Memcached. Установите соответствующий адаптер и настройте в конфигурации.

### Медленная загрузка страниц из-за множества SQL-запросов

**Причина:** Проблема N+1.

**Решение:** Используйте жадную загрузку (eager loading) в Axiom ORM:

```php
$users = Orm::table('users')->with('posts')->get();
```

## Проблемы с окружениями

### Конфигурация окружения не загружается

**Причина:** Переменная `APP_ENV` не установлена или установлена неверно.

**Решение:** Убедитесь, что переменная установлена на уровне веб-сервера или в `.env` файле. Проверьте, что файл окружения существует (`app/config/environment/your_env.json`).

### Настройки из production.json не применяются

**Причина:** Возможно, файл имеет синтаксическую ошибку в JSON.

**Решение:** Проверьте валидность JSON с помощью онлайн-валидатора или команды:

```bash
php -r "json_decode(file_get_contents('app/config/environment/production.json')); echo json_last_error_msg();"
```

## Проблемы с консольными командами

### Команда `arc` не найдена

**Причина:** Файл `bin/arc` не исполняемый или путь не указан.

**Решение:** Дайте права на выполнение:

```bash
chmod +x bin/arc
```

И запускайте как `php bin/arc`.

### Ошибка "Service not found" при выполнении консольной команды

**Причина:** Контейнер не инициализирован в консольном окружении.

**Решение:** Убедитесь, что команда использует правильный bootstrap. Консольные команды Architect должны запускаться через `bin/arc`, который загружает контейнер.

## Проблемы с обновлением версий

### После обновления Composer пакетов приложение перестало работать

**Причина:** Новая версия может содержать breaking changes.

**Решение:**
1. Проверьте CHANGELOG пакетов.
2. Откатитесь на предыдущую версию, пока не адаптируете код.
3. Убедитесь, что версии Architect и его компонентов совместимы.

## Проблемы с Docker

### Контейнеры Architect не могут подключиться к MySQL

**Причина:** Сетевые настройки Docker: сервис MySQL недоступен по указанному хосту.

**Решение:** Вместо `localhost` используйте имя сервиса Docker (например, `mysql`). Проверьте `docker-compose.yml` и настройки сети.

### Файлы изменяются, но изменения не отражаются в контейнере

**Причина:** Том (volume) не подключён или подключён неправильно.

**Решение:** Проверьте маппинг томов в `docker-compose.yml`. Пересоздайте контейнеры после изменения.

## Проблемы с веб-сокетами и асинхронными задачами

Architect не имеет встроенной поддержки веб-сокетов. Для реализации требуется внешний сервер (например, Ratchet) и интеграция через отдельный процесс.

## Если проблема не описана

Если вы столкнулись с проблемой, которой нет в этом списке:

1. Проверьте логи (`app/logs/`).
2. Включите отображение ошибок PHP.
3. Используйте Debug Panel для анализа запроса.
4. Создайте issue на [GitHub](https://github.com/architect-framework/architect-red2/issues) с подробным описанием.

## Заключение

Большинство проблем решаются проверкой конфигурации, прав доступа и логов. Следите за обновлениями фреймворка, где исправляются известные баги.

Дополнительные сведения см. в разделах [Устранение неполадок](troubleshooting.md) (если такой файл есть) или [Конфигурация](configuration.md).
